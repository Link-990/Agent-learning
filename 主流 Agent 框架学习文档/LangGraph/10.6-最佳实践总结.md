# 10.6 从 Kami Code 学到的 LangGraph 最佳实践

通过深入分析 Kami Code 项目，我们总结出以下 LangGraph 的最佳实践。

---

## 1. 流式输出是标配

Kami Code 全程使用流式输出——用户不需要等待 Agent 执行完毕，而是实时看到进展。

**最佳实践**：
- 优先使用 `stream_mode="messages"` 获取消息级流式输出
- 准备好降级方案（state stream mode）
- 用 `stream_events()` 统一对外接口

---

## 2. 用 metadata 区分消息来源

LangGraph 的流式输出是"混合"的——所有节点的消息都在一个流里。通过 `metadata["langgraph_node"]` 区分消息来源。

**最佳实践**：
```python
node = chunk[1].get("langgraph_node")
if node == "model":
    # 处理 LLM 输出
elif node == "tools":
    # 处理工具调用
elif node == "input":
    # 处理用户输入回显
```

---

## 3. 适配器模式隔离底层框架

Kami Code 通过 `deepagents_adapter.py` 隔离了底层框架的差异。如果将来换框架（比如从 deepagents 换成其他），只需要改适配器，上层代码不用动。

**最佳实践**：
- 定义统一的 Agent 接口（`invoke` / `stream` / `stream_events`）
- 用适配器封装底层框架
- 对外暴露统一的事件格式

---

## 4. 降级策略保证兼容性

Kami Code 的三级降级策略：

```
stream_events() → messages stream → state stream
```

**最佳实践**：
- 优先用高级 API
- 捕获异常，降级到低级 API
- 保证在所有环境下都能工作

---

## 5. Token 追踪不可忽视

Kami Code 在适配器层统一追踪 Token 使用量。

**最佳实践**：
- 用 `UsageAccumulator` 累计多次调用
- 从 `AIMessage.usage_metadata` 提取 Token 信息
- 只从 `model` 节点的 assistant 消息中提取

---

## 6. ReAct 模式是生产标配

Kami Code 底层的 LangGraph 图是典型的 ReAct 模式——`input → model → tools → model → ...`

**最佳实践**：
- ReAct 模式是经过大量验证的 Agent 架构
- 适合大多数需要工具调用的场景
- 简单、可靠、易于调试

---

## 7. 测试中模拟 LangGraph 输出

Kami Code 的测试文件中，大量模拟 LangGraph 的流式输出格式：

```python
# 模拟 LangGraph 的输出
yield (StreamMessage("tool", '{"questions": []}'), {"langgraph_node": "tools"})
yield (StreamMessage("human", "hidden user echo"), {"langgraph_node": "input"})
yield (StreamMessage("ai", "visible answer"), {"langgraph_node": "model"})
```

**最佳实践**：
- 在测试中模拟 LangGraph 的输出格式
- 覆盖各种节点类型（model、tools、input）
- 测试消息过滤和 Token 提取逻辑

---

## 总结：你可以直接用的设计模式

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **适配器模式** | 封装底层框架差异 | 需要切换底层框架时 |
| **降级策略** | 高级 API 失败时降级 | 保证兼容性 |
| **metadata 过滤** | 从混合流中按来源过滤 | 消费 LangGraph 流式输出 |
| **Token 累计** | 用 Accumulator 统计 | 追踪成本和性能 |
| **ReAct 模式** | model ⇄ tools 循环 | 大多数 Agent 场景 |
| **统一事件接口** | 对外暴露统一格式 | 前端集成、日志、监控 |
