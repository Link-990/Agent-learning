## 10.2 四个框架的定位对比

| 框架 | 定位 | 语言 | 核心能力 |
|------|------|------|---------|
| **LangGraph** | 低层工作流编排 | Python | StateGraph、持久化、HITL |
| **LangChain** | 中层 Agent 开发 | Python | create_agent()、Middleware |
| **Deep Agents** | 上层复杂任务 | Python | 文件系统、子 Agent、规划 |
| **Pi Agent** | AI Coding Agent | TypeScript | Extension、树状历史、自修改 |

---

## 10.3 技术栈对比

| 特性 | LangGraph | LangChain | Deep Agents | Pi Agent |
|------|-----------|-----------|-------------|----------|
| 语言 | Python | Python | Python | TypeScript |
| Agent 创建 | StateGraph | create_agent() | create_deep_agent() | createAgentSession() |
| 工具定义 | @tool | @tool | @tool | defineTool() |
| 工作流编排 | 核心能力 | 无（用 LangGraph） | 内置 | 无（用 Extension） |
| 持久化 | Checkpointer + Store | 无 | Backend 系统 | SessionManager |
| 子 Agent | 手动编排 | 无 | subagents + task() | 通过 Extension |
| Middleware | 无 | ✅ 核心能力 | 继承 LangChain | Hooks |
| 文件系统 | 无 | 无 | ✅ 内置 | 内置工具 |
| 自修改 | 无 | 无 | 无 | ✅ 独特能力 |
| 流式输出 | stream_events() | stream_events() | stream_events() | subscribe() |

## 10.4 适用场景对比

| 场景 | 推荐框架 |
|------|---------|
| 简单 Agent（工具调用） | LangChain |
| 复杂工作流编排 | LangGraph |
| 需要文件读写的复杂任务 | Deep Agents |
| AI Coding Agent | Pi Agent |
| 需要持久化 + HITL | LangGraph |
| 多 Agent 协作 | Deep Agents |
| 需要极致定制 | Pi Agent |
| 快速原型 | LangChain |
| 生产部署 | Deep Agents + LangGraph |

---

## 10.5 学习路径建议

### 推荐顺序

```
1. LangGraph（基础）→ 理解工作流编排
2. LangChain（上层）→ 理解 Agent 开发
3. Deep Agents（全家桶）→ 理解复杂任务
4. Pi Agent（独立生态）→ 理解 Coding Agent
```

### 为什么这个顺序？

- LangGraph 是底层基础，LangChain 和 Deep Agents 都构建在它之上
- Deep Agents 需要 LangChain 和 LangGraph 的知识
- Pi Agent 是独立生态，可以并行学习

---

## 10.6 总结

### 四个框架的核心价值

| 框架 | 一句话 |
|------|-------|
| **LangGraph** | 用"图"编排 Agent 的工作流 |
| **LangChain** | 最小化的 Agent 开发框架 |
| **Deep Agents** | 面向复杂多步骤任务的全家桶 |
| **Pi Agent** | 极简但高度可扩展的 Coding Agent |

### 共同点

- 都基于 LLM + 工具调用
- 都支持流式输出
- 都支持多 Provider
- 都支持 Middleware/Hooks 扩展

### 差异点

- **编排方式**：图 vs 函数 vs 全家桶 vs Extension
- **语言**：Python vs TypeScript
- **复杂度**：低层 vs 中层 vs 上层 vs 独立
- **定制方式**：节点/边 vs Middleware vs Backend vs Extension

### 选择原则

1. **从需求出发**：你需要什么能力？
2. **从团队出发**：团队熟悉什么语言？
3. **从规模出发**：项目复杂度如何？
4. **可以混合使用**：不同框架可以组合
