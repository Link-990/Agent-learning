# 8.2 Supervisor 模式：一个"领导"分配任务

Supervisor 模式是多 Agent 系统中最常见、最容易理解的模式——一个 Supervisor Agent 扮演"领导"角色，分析任务，然后分配给合适的 Worker Agent 执行。

---

## 架构

```
用户输入
    ↓
[Supervisor]
    ↓ 分配任务
    ├─ [Worker A] → 返回结果
    ├─ [Worker B] → 返回结果
    └─ [Worker C] → 返回结果
    ↓
[Supervisor] 汇总
    ↓
最终输出
```

---

## 实现原理

在 LangGraph 中，Supervisor 模式通过**条件路由**实现：

1. Supervisor 节点分析任务，决定交给哪个 Worker
2. 条件边根据 Supervisor 的输出，路由到对应的 Worker
3. Worker 执行完任务后，回到 Supervisor
4. Supervisor 判断是否完成，或者继续分配任务

---

## 完整代码示例

### 第一步：定义 Worker Agent

```python
from langchain_openai import ChatOpenAI

# 研究员 Agent
researcher_llm = ChatOpenAI(model="gpt-4o-mini")

def researcher_node(state):
    """研究员：搜索资料"""
    messages = state["messages"]
    response = researcher_llm.invoke([
        {"role": "system", "content": "你是研究专家，专注搜索和分析信息。请提供详细的研究结果。"},
        *messages
    ])
    return {"messages": [response], "next_worker": "researcher"}

# 写手 Agent
writer_llm = ChatOpenAI(model="gpt-4o")

def writer_node(state):
    """写手：撰写内容"""
    messages = state["messages"]
    response = writer_llm.invoke([
        {"role": "system", "content": "你是写作专家，专注生成高质量的文章。"},
        *messages
    ])
    return {"messages": [response], "next_worker": "writer"}

# 审核员 Agent
reviewer_llm = ChatOpenAI(model="gpt-4o-mini")

def reviewer_node(state):
    """审核员：审核内容"""
    messages = state["messages"]
    response = reviewer_llm.invoke([
        {"role": "system", "content": "你是审核专家，检查内容的准确性和质量。给出修改建议。"},
        *messages
    ])
    return {"messages": [response], "next_worker": "reviewer"}
```

### 第二步：定义 Supervisor

```python
from typing import TypedDict
from langchain_core.messages import BaseMessage

class MultiAgentState(TypedDict):
    messages: list[BaseMessage]
    next_worker: str

supervisor_llm = ChatOpenAI(model="gpt-4o-mini")

def supervisor_node(state: MultiAgentState):
    """Supervisor：分析任务，分配给合适的 Worker"""
    messages = state["messages"]
    
    response = supervisor_llm.invoke([
        {"role": "system", "content": """
你是一个团队领导。根据当前对话，决定下一步应该由谁来处理。

可用的 Worker：
- researcher：研究员，负责搜索资料和分析数据
- writer：写手，负责撰写文章和内容
- reviewer：审核员，负责审核内容质量
- FINISH：任务已完成，可以结束

请只回复一个词：researcher / writer / reviewer / FINISH
"""},
        *messages
    ])
    
    # 解析 Supervisor 的决策
    decision = response.content.strip().lower()
    
    if "finish" in decision:
        return {"messages": [response], "next_worker": "FINISH"}
    elif "researcher" in decision:
        return {"messages": [response], "next_worker": "researcher"}
    elif "writer" in decision:
        return {"messages": [response], "next_worker": "writer"}
    elif "reviewer" in decision:
        return {"messages": [response], "next_worker": "reviewer"}
    else:
        return {"messages": [response], "next_worker": "FINISH"}
```

### 第三步：构建图

```python
from langgraph.graph import StateGraph, START, END

def route_after_supervisor(state):
    """根据 Supervisor 的决策，路由到对应的 Worker"""
    next_worker = state["next_worker"]
    
    if next_worker == "FINISH":
        return "end"
    else:
        return next_worker

# 构建图
graph = StateGraph(MultiAgentState)

# 添加节点
graph.add_node("supervisor", supervisor_node)
graph.add_node("researcher", researcher_node)
graph.add_node("writer", writer_node)
graph.add_node("reviewer", reviewer_node)

# 添加边
graph.add_edge(START, "supervisor")

# Supervisor 之后，根据决策路由
graph.add_conditional_edges(
    "supervisor",
    route_after_supervisor,
    {
        "researcher": "researcher",
        "writer": "writer",
        "reviewer": "reviewer",
        "end": END
    }
)

# Worker 完成后，回到 Supervisor
graph.add_edge("researcher", "supervisor")
graph.add_edge("writer", "supervisor")
graph.add_edge("reviewer", "supervisor")

# 编译
app = graph.compile()
```

**流程图**：

```
START → supervisor → 决策
              ↑          ├─ researcher → supervisor
              ↑          ├─ writer → supervisor
              ↑          ├─ reviewer → supervisor
              └── FINISH ←┘
```

result = app.invoke({

## Supervisor 模式的关键点

### 1. Supervisor 的 Prompt 设计

Supervisor 的 Prompt 要清晰描述每个 Worker 的职责：

```python
supervisor_prompt = """
可用的 Worker：
- researcher：研究员，负责搜索资料和分析数据
- writer：写手，负责撰写文章和内容
- reviewer：审核员，负责审核内容质量
- FINISH：任务已完成

请根据当前任务，选择合适的 Worker。只回复 Worker 的名字。
"""
```

### 2. Worker 的 Prompt 设计

每个 Worker 的 Prompt 要专注：

```python
researcher_prompt = "你是研究专家，专注搜索和分析信息。"
writer_prompt = "你是写作专家，专注生成高质量的内容。"
```

### 3. 循环终止条件

Supervisor 必须能够判断"任务完成"，否则会无限循环：

```python
if "finish" in decision:
    return "end"
```

---

## Supervisor 模式的优缺点

### 优点

- ✅ 结构清晰，容易理解
- ✅ 集中控制，容易调试
- ✅ 可以动态分配任务
- ✅ 适合"流水线"类型的任务

### 缺点

- ❌ Supervisor 是单点瓶颈
- ❌ 所有通信都要经过 Supervisor
- ❌ Supervisor 的决策质量影响整个系统

---

## 小结

Supervisor 模式：
- 一个 Supervisor 负责分配任务
- Worker 负责执行具体任务
- 通过条件路由实现动态分配
- 适合流水线类型的任务
