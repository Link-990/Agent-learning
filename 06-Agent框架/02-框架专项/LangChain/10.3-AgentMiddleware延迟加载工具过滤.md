# 10.3 AgentMiddleware：延迟加载工具过滤

Kami Code 有几十个工具，但不可能每次都把所有工具暴露给 LLM——Token 消耗太大，LLM 也容易混乱。

解决方案：**延迟加载**——只在需要时才让工具对 LLM 可见。

---

## 核心代码

```python
# kamiagent/agent/tool_search_middleware.py
try:
    from langchain.agents.middleware import AgentMiddleware
except ImportError:
    class AgentMiddleware:  # 兼容没有 LangChain 的环境
        pass

class DeferredToolMiddleware(AgentMiddleware):
    def __init__(self, activation_state):
        self.activation_state = activation_state
    
    def visible_tools(self, tools):
        visible = []
        for tool in tools:
            metadata = getattr(tool, "metadata", {})
            
            # 不是延迟加载的工具，直接可见
            if not metadata.get("defer_loading", False):
                visible.append(tool)
                continue
            
            # 延迟加载的工具，只有激活后才可见
            public_name = metadata.get("public_name")
            if self.activation_state.is_active(public_name):
                visible.append(tool)
        
        return visible
    
    def wrap_model_call(self, request, handler):
        # 在 LLM 调用前，过滤工具列表
        filtered = self.visible_tools(request.tools)
        return handler(request.override(tools=filtered))
    
    async def awrap_model_call(self, request, handler):
        filtered = self.visible_tools(request.tools)
        return await handler(request.override(tools=filtered))
```

---

## 解读

1. **`wrap_model_call`**：拦截 LLM 调用
2. **`visible_tools`**：过滤工具列表
3. **`request.override(tools=filtered)`**：用过滤后的工具列表替换原列表
4. **优雅降级**：`try/except ImportError`，没有 LangChain 也能运行

---

## 工作流程

```
LLM 调用前
    ↓
[DeferredToolMiddleware.wrap_model_call]
    ↓
过滤工具列表：
    - 非延迟加载的工具 → 保留
    - 延迟加载且未激活 → 移除
    - 延迟加载且已激活 → 保留
    ↓
[handler(request.override(tools=filtered_tools))]
    ↓
LLM 只看到过滤后的工具
```

---

## 设计亮点

- 用 Middleware 实现了"按需加载"——LLM 只看到当前需要的工具
- `metadata["defer_loading"]` 是工具级别的标记
- 同步和异步都支持
