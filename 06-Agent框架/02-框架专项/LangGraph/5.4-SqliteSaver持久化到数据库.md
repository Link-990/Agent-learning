# 5.4 SqliteSaver：持久化到数据库

`SqliteSaver` 是 LangGraph 提供的持久化 Checkpointer——它把 checkpoint 保存到 **SQLite 数据库**中。

与 MemorySaver 相比，SqliteSaver 的最大优势是：**程序重启后，状态依然保留**。

---

## SqliteSaver 的特点

### 优点

1. **持久化**：程序重启后，状态依然存在
2. **轻量级**：SQLite 是单文件数据库，无需单独的数据库服务器
3. **适合小型应用**：个人项目、小团队、中等规模的应用
4. **与 MemorySaver API 完全一致**：迁移只需改 1 行代码

### 缺点

1. **并发限制**：SQLite 不适合高并发场景
2. **单机**：无法跨服务器共享
3. **文件锁**：多进程同时写入可能出问题

---

## 安装

SqliteSaver 需要额外安装：

```bash
pip install langgraph-checkpoint-sqlite
```

---

## 基本用法

### 1. 创建 SqliteSaver

```python
from langgraph.checkpoint.sqlite import SqliteSaver

# 方式 1：指定数据库文件路径
checkpointer = SqliteSaver.from_conn_string("checkpoints.db")

# 方式 2：使用内存数据库（相当于 MemorySaver）
checkpointer = SqliteSaver.from_conn_string(":memory:")
```

### 2. 绑定到 Graph

```python
from langgraph.graph import StateGraph, MessagesState, START, END

graph = StateGraph(MessagesState)
# ... 添加节点 ...

app = graph.compile(checkpointer=checkpointer)
```

### 3. 使用（与 MemorySaver 完全一样）

```python
result = app.invoke(
    {"messages": [{"role": "user", "content": "你好"}]},
    config={"configurable": {"thread_id": "user_1"}}
)
```

## 完整示例：持久化的对话机器人

```python
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.checkpoint.sqlite import SqliteSaver
from langchain_openai import ChatOpenAI
from dotenv import load_dotenv

load_dotenv()

# 创建 LLM
llm = ChatOpenAI(model="gpt-4o-mini")

# 定义节点
def chat(state: MessagesState):
    response = llm.invoke(state["messages"])
    return {"messages": [response]}

# 构建图
graph = StateGraph(MessagesState)
graph.add_node("chat", chat)
graph.add_edge(START, "chat")
graph.add_edge("chat", END)

# 使用 SqliteSaver
checkpointer = SqliteSaver.from_conn_string("chat_history.db")
app = graph.compile(checkpointer=checkpointer)

# 对话函数
def chat_with_agent(user_input: str, thread_id: str):
    result = app.invoke(
        {"messages": [{"role": "user", "content": user_input}]},
        config={"configurable": {"thread_id": thread_id}}
    )
    return result["messages"][-1].content

# 测试
if __name__ == "__main__":
    # 第一次运行
    print("=== 第一次运行 ===")
    response = chat_with_agent("我叫 Alice", "user_1")
    print(f"AI: {response}")
    
    response = chat_with_agent("我喜欢编程", "user_1")
    print(f"AI: {response}")
    
    print("\n程序退出，重新启动...\n")
    
    # ⚠️ 模拟程序重启：重新创建 checkpointer 和 app
    checkpointer = SqliteSaver.from_conn_string("chat_history.db")
    app = graph.compile(checkpointer=checkpointer)
    
    # 第二次运行
    print("=== 第二次运行（程序重启后） ===")
    response = chat_with_agent("我叫什么名字？", "user_1")
    print(f"AI: {response}")  # 依然记得：你叫 Alice
    
    response = chat_with_agent("我喜欢什么？", "user_1")
    print(f"AI: {response}")  # 依然记得：你喜欢编程
```

输出：

```
=== 第一次运行 ===
AI: 很高兴认识你，Alice！
AI: 编程是一项很棒的技能！

程序退出，重新启动...

=== 第二次运行（程序重启后） ===
AI: 你叫 Alice。
AI: 你喜欢编程。
```

**关键点**：程序重启后，状态依然保留！

## SQLite 数据库结构

SqliteSaver 会创建以下表：

### 1. checkpoints 表

```sql
CREATE TABLE checkpoints (
    thread_id TEXT NOT NULL,
    checkpoint_id TEXT NOT NULL,
    parent_checkpoint_id TEXT,
    checkpoint BLOB NOT NULL,
    metadata BLOB,
    PRIMARY KEY (thread_id, checkpoint_id)
);
```

字段说明：
- `thread_id`：对话线程 ID
- `checkpoint_id`：checkpoint 的唯一 ID
- `parent_checkpoint_id`：父 checkpoint 的 ID（用于链式回溯）
- `checkpoint`：序列化的 checkpoint 数据（二进制）
- `metadata`：元数据（时间戳、版本等）

### 2. writes 表（可选）

用于记录每个节点的写入操作。

## 查看数据库内容

### 使用 SQLite 命令行工具

```bash
sqlite3 checkpoints.db

# 查看所有表
.tables

# 查看 checkpoints 表结构
.schema checkpoints

# 查看所有 thread_id
SELECT DISTINCT thread_id FROM checkpoints;

# 查看某个 thread 的 checkpoint 数量
SELECT COUNT(*) FROM checkpoints WHERE thread_id = 'user_1';

# 退出
.quit
```

### 使用 Python

```python
import sqlite3

conn = sqlite3.connect("checkpoints.db")
cursor = conn.cursor()

# 查看所有 thread_id
cursor.execute("SELECT DISTINCT thread_id FROM checkpoints")
threads = cursor.fetchall()
print("所有对话线程:", threads)

# 查看某个 thread 的 checkpoint 数量
cursor.execute("SELECT COUNT(*) FROM checkpoints WHERE thread_id = ?", ("user_1",))
count = cursor.fetchone()[0]
print(f"user_1 有 {count} 个 checkpoint")

conn.close()
```

## 异步版本：AsyncSqliteSaver

如果你的应用是异步的（使用 `async`/`await`），可以用 `AsyncSqliteSaver`。

### 安装

```bash
pip install langgraph-checkpoint-sqlite aiosqlite
```

### 使用

```python
from langgraph.checkpoint.sqlite.aio import AsyncSqliteSaver

async def main():
    # 创建异步 checkpointer
    async with AsyncSqliteSaver.from_conn_string("checkpoints.db") as checkpointer:
        app = graph.compile(checkpointer=checkpointer)
        
        # 异步调用
        result = await app.ainvoke(
            {"messages": [{"role": "user", "content": "你好"}]},
            config={"configurable": {"thread_id": "user_1"}}
        )

import asyncio
asyncio.run(main())
```

## 清理旧数据

长期运行后，数据库会积累大量 checkpoint。可以定期清理：

### 方法 1：删除旧的 thread

```python
import sqlite3

conn = sqlite3.connect("checkpoints.db")
cursor = conn.cursor()

# 删除某个 thread 的所有 checkpoint
cursor.execute("DELETE FROM checkpoints WHERE thread_id = ?", ("old_thread",))

conn.commit()
conn.close()
```

### 方法 2：删除超过 N 天的 checkpoint

```python
import sqlite3
from datetime import datetime, timedelta

conn = sqlite3.connect("checkpoints.db")
cursor = conn.cursor()

# 计算 30 天前的时间戳
cutoff = datetime.now() - timedelta(days=30)

# 删除旧的 checkpoint（需要从 metadata 里解析时间戳）
# 具体实现取决于 metadata 的结构
cursor.execute("DELETE FROM checkpoints WHERE ...")

conn.commit()
conn.close()
```

### 方法 3：只保留每个 thread 的最近 N 个 checkpoint

```python
# 获取所有 thread
history = list(app.get_state_history(
    config={"configurable": {"thread_id": "user_1"}}
))

# 只保留最近 10 个
if len(history) > 10:
    old_checkpoint_ids = [state.config["configurable"]["checkpoint_id"] 
                          for state in history[10:]]
    
    # 删除旧的 checkpoint
    cursor.execute(
        f"DELETE FROM checkpoints WHERE checkpoint_id IN ({','.join(['?']*len(old_checkpoint_ids))})",
        old_checkpoint_ids
    )
```

## SqliteSaver vs MemorySaver

| 特性 | MemorySaver | SqliteSaver |
|------|-------------|-------------|
| 持久化 | ❌ 程序退出后丢失 | ✅ 程序退出后保留 |
| 速度 | ⭐⭐⭐⭐⭐ 极快 | ⭐⭐⭐⭐ 快 |
| 内存占用 | 大（所有数据在内存） | 小（只缓存部分数据） |
| 适用场景 | 开发、测试 | 小型生产环境 |
| 并发支持 | 无限制 | 有限制 |
| API | 完全一致 | 完全一致 |

---

## 生产环境建议

### 小型应用（< 1000 用户）

```python
checkpointer = SqliteSaver.from_conn_string("checkpoints.db")
```

✅ SqliteSaver 够用了。

### 中型应用（1000 - 10000 用户）

```python
from langgraph.checkpoint.postgres import PostgresSaver

checkpointer = PostgresSaver.from_conn_string(
    "postgresql://user:password@localhost/dbname"
)
```

✅ 使用 PostgreSQL。

### 大型应用（> 10000 用户）

```python
from langgraph.checkpoint.redis import RedisSaver

checkpointer = RedisSaver.from_conn_string("redis://localhost:6379")
```

✅ 使用 Redis + PostgreSQL 混合方案。

## 常见问题

### Q1: 数据库文件可以删除吗？

**可以**。删除后，所有 checkpoint 会丢失，相当于重新开始。

```bash
rm checkpoints.db
```

### Q2: 可以用同一个数据库文件给多个应用吗？

**可以**，但不推荐。不同应用的 State 结构可能不同，容易出错。

推荐：每个应用一个数据库文件。

### Q3: 数据库文件可以备份吗？

**可以**。直接复制 `.db` 文件即可：

```bash
cp checkpoints.db checkpoints_backup.db
```

### Q4: SqliteSaver 支持多进程吗？

**有限支持**。SQLite 支持多进程读，但多进程写可能会出现锁冲突。

如果需要多进程写，使用 PostgreSQL 或 Redis。

## 小结

SqliteSaver 的特点：

**优点**：
- ✅ 持久化（程序重启后状态保留）
- ✅ 轻量级（单文件数据库）
- ✅ API 与 MemorySaver 一致
- ✅ 适合小型应用

**缺点**：
- ❌ 并发限制
- ❌ 单机（无法跨服务器）

**使用场景**：
- 个人项目
- 小团队应用
- 中等规模的生产环境

**从 MemorySaver 迁移**：只需改 1 行代码：

```python
# 开发阶段
checkpointer = MemorySaver()

# 生产环境
checkpointer = SqliteSaver.from_conn_string("checkpoints.db")
```
