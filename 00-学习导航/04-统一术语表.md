# 统一术语表

| 术语 | 含义 | 关键边界 |
| --- | --- | --- |
| Task | 用户提交的逻辑任务定义 | 可以被多次执行 |
| Run | 某个 Task 的一次执行实例 | 有唯一 run_id，有独立生命周期 |
| State | 一个 Run 当前的结构化事实 | 由 Runtime 管理，不等于完整聊天记录 |
| Event | 已经发生、可以记录和审计的事实 | 不能把未来计划当成已发生事实 |
| Tool | 经过注册、参数校验和权限检查的外部能力 | 模型只能提出调用意图 |
| Checkpoint | 包含 State、下一步位置和版本的恢复快照 | 用于恢复，不等于所有历史 Event |
| Decision | 模型提出的下一步候选 | 必须经过 Runtime 策略门 |
| Context | 某次模型调用实际看到的输入 | 受预算、来源和权限约束 |
| Memory | 跨 Run 保留的经过筛选的信息 | 需要来源、TTL、租户和删除策略 |
| Workflow | 由代码或规则控制的确定性编排 | 可包含 Agent 节点 |
| Agent | 围绕目标进行动态决策和受控行动的系统 | 不是“更强的模型” |

## Run 生命周期

```text
created -> queued -> running
                       |
       +---------------+----------------+
       v                                v
waiting_for_tool                 waiting_for_human
       |                                |
       +-------------> running <--------+
                                      |
                         +------------+------------+
                         v                         v
                    succeeded                  failed / cancelled
```

resumed 是一个事件，不是生命周期状态。Workflow 的业务子状态也不能替代 Run 生命周期。
