# 5.6 InMemoryStore 与持久化 Store

上一节我们学习了 Store 的基本概念和 InMemoryStore 的用法。这一节我们深入对比不同的 Store 实现，并学习如何选择合适的 Store。

---

## Store 的实现类型

LangGraph 提供多种 Store 实现：

| Store 类型 | 存储位置 | 持久化 | 语义搜索 | 适用场景 |
|-----------|---------|-------|---------|---------|
| InMemoryStore | 内存 | ❌ | ✅ | 开发、测试 |
| PostgresStore | PostgreSQL | ✅ | ✅ | 生产环境 |
| RedisStore | Redis | ✅ | ❌ | 高速缓存 |

---

## InMemoryStore 详解

### 特点

**优点**：
- ✅ 零配置
- ✅ 快速
- ✅ 支持语义搜索（通过嵌入向量）

**缺点**：
- ❌ 不持久化（程序退出后丢失）
- ❌ 内存占用
- ❌ 不能跨进程共享

### 基本用法

```python
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()

# 保存数据
store.put(("user", "alice"), "language", {"lang": "zh-CN"})

# 读取数据
item = store.get(("user", "alice"), "language")
print(item.value)

# 搜索数据
items = store.search(("user", "alice"))
for item in items:
    print(item.key, item.value)

# 删除数据
store.delete(("user", "alice"), "language")
```

### 语义搜索

InMemoryStore 支持基于嵌入向量的语义搜索：

```python
from langgraph.store.memory import InMemoryStore
from langchain_openai import OpenAIEmbeddings

# 创建 Store，配置嵌入模型
embeddings = OpenAIEmbeddings()
store = InMemoryStore(
    index={
        "embed": embeddings,
        "dims": 1536  # OpenAI 的嵌入维度
    }
)

# 保存文档
store.put(("documents",), "doc1", {"text": "如何申请退款？请联系客服。"})
store.put(("documents",), "doc2", {"text": "发货一般需要 3-5 个工作日。"})
store.put(("documents",), "doc3", {"text": "我们支持支付宝、微信支付。"})

# 语义搜索
results = store.search(
    namespace=("documents",),
    query="退货流程",  # 语义相似的查询
    limit=2
)

for item in results:
    print(item.value)
```

输出：

```
{"text": "如何申请退款？请联系客服。"}
{"text": "发货一般需要 3-5 个工作日。"}
```

## 持久化 Store：PostgresStore

在生产环境中，应该使用持久化的 Store。

### 安装

```bash
pip install langgraph-store-postgres psycopg2-binary
```

### 创建 PostgresStore

```python
from langgraph.store.postgres import PostgresStore

store = PostgresStore.from_conn_string(
    "postgresql://user:password@localhost:5432/dbname"
)
```

### 与 InMemoryStore API 完全一致

```python
# API 完全一样
store.put(("user", "alice"), "language", {"lang": "zh-CN"})
item = store.get(("user", "alice"), "language")
items = store.search(("user", "alice"))
store.delete(("user", "alice"), "language")
```

### 支持语义搜索

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings()

store = PostgresStore.from_conn_string(
    "postgresql://user:password@localhost:5432/dbname",
    index={
        "embed": embeddings,
        "dims": 1536
    }
)

# 语义搜索（与 InMemoryStore 一样）
results = store.search(
    namespace=("documents",),
    query="退货",
    limit=5
)
```

## 选择合适的 Store

### 开发阶段

```python
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()
```

✅ 快速开发，不需要配置数据库。

### 小型应用（用户 < 1000）

```python
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()
```

✅ InMemoryStore 可能够用（如果不需要持久化）。

或者：

```python
# 使用 PostgreSQL 持久化
from langgraph.store.postgres import PostgresStore

store = PostgresStore.from_conn_string("postgresql://...")
```

### 中型应用（用户 1000 - 10000）

```python
from langgraph.store.postgres import PostgresStore

store = PostgresStore.from_conn_string("postgresql://...")
```

✅ 推荐 PostgreSQL。

### 大型应用（用户 > 10000）

```python
# 使用 PostgreSQL + Redis 混合方案
from langgraph.store.postgres import PostgresStore
from langgraph.store.redis import RedisStore

# 长期数据用 PostgreSQL
persistent_store = PostgresStore.from_conn_string("postgresql://...")

# 热数据用 Redis 缓存
cache_store = RedisStore.from_conn_string("redis://localhost:6379")
```

## Store 的数据结构

### InMemoryStore

内部用字典存储：

```python
{
    ("user", "alice"): {
        "language": {
            "value": {"lang": "zh-CN"},
            "created_at": "2024-01-15T10:00:00Z",
            "updated_at": "2024-01-15T10:00:00Z"
        },
        "theme": {
            "value": {"theme": "dark"},
            "created_at": "2024-01-15T10:01:00Z",
            "updated_at": "2024-01-15T10:01:00Z"
        }
    }
}
```

### PostgresStore

创建以下表：

```sql
CREATE TABLE store (
    namespace TEXT[] NOT NULL,
    key TEXT NOT NULL,
    value JSONB NOT NULL,
    created_at TIMESTAMP NOT NULL,
    updated_at TIMESTAMP NOT NULL,
    embedding VECTOR(1536),  -- 如果启用了语义搜索
    PRIMARY KEY (namespace, key)
);
```

## 从 InMemoryStore 迁移到 PostgresStore

迁移非常简单——只需改 1 行代码：

### 开发阶段

```python
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()
```

### 生产环境

```python
from langgraph.store.postgres import PostgresStore

store = PostgresStore.from_conn_string(
    "postgresql://user:password@localhost:5432/dbname"
)
```

其他代码**完全不变**！

---

## 实战：将 InMemoryStore 的数据迁移到 PostgresStore

```python
from langgraph.store.memory import InMemoryStore
from langgraph.store.postgres import PostgresStore

# 步骤 1：从 InMemoryStore 导出数据
in_memory_store = InMemoryStore()

# 假设已经有一些数据
in_memory_store.put(("user", "alice"), "language", {"lang": "zh-CN"})
in_memory_store.put(("user", "alice"), "theme", {"theme": "dark"})
in_memory_store.put(("user", "bob"), "language", {"lang": "en-US"})

# 导出所有数据
all_items = []
# （需要遍历所有 namespace，InMemoryStore 可能需要提供导出接口）

# 步骤 2：导入到 PostgresStore
postgres_store = PostgresStore.from_conn_string("postgresql://...")

for item in all_items:
    postgres_store.put(item.namespace, item.key, item.value)

print("迁移完成！")
```

## Store 的最佳实践

### 1. 使用清晰的 namespace 结构

**好的示例**：

```python
("user", user_id)                    # 用户相关
("user", user_id, "preferences")     # 用户偏好
("user", user_id, "history")         # 用户历史
("faq",)                             # FAQ
("product", product_id)              # 产品信息
```

**不好的示例**：

```python
("data",)                            # 太泛化
("user_data", user_id)               # 不一致的命名
(user_id,)                           # 缺少类型前缀
```

### 2. 值的结构化

**好的示例**：

```python
store.put(("user", "alice"), "preferences", {
    "language": "zh-CN",
    "theme": "dark",
    "notifications": {
        "email": True,
        "sms": False
    }
})
```

**不好的示例**：

```python
store.put(("user", "alice"), "pref1", "zh-CN")  # 不结构化

```

## Store vs 数据库

有人可能会问：**Store 和普通数据库有什么区别？为什么不直接用数据库？**

### Store 的优势

1. **与 LangGraph 集成**
   - 可以在 @task 里自动注入
   - 不需要手动管理连接

2. **语义搜索**
   - 内置嵌入向量搜索
   - 不需要额外配置向量数据库

3. **简化的 API**
   - `put` / `get` / `search` / `delete`
   - 不需要写 SQL

4. **命名空间**
   - 天然的层级化组织
   - 适合多租户应用

### 何时用 Store，何时用数据库？

| 场景 | 推荐 |
|------|-----|
| 用户偏好设置 | Store |
| 知识库、FAQ | Store（带语义搜索） |
| 对话记忆 | Store |
| 业务数据（订单、商品） | 数据库 |
| 复杂的关系查询 | 数据库 |
| 报表、统计 | 数据库 |

**原则**：Store 适合**非结构化、需要语义搜索、与 Agent 紧密相关**的数据。

## 小结

Store 的实现类型：

| Store | 持久化 | 语义搜索 | 适用场景 |
|-------|-------|---------|---------|
| InMemoryStore | ❌ | ✅ | 开发、测试 |
| PostgresStore | ✅ | ✅ | 生产环境 |

选择建议：
- **开发阶段**：InMemoryStore
- **生产环境**：PostgresStore

迁移：只需改 1 行代码。

最佳实践：
- 清晰的 namespace 结构
- 结构化的 value
- 定期清理旧数据
- 使用版本控制
