# 1.1 一句话理解 LangGraph：用"图"来编排 AI Agent 的工作流

如果只用一句话来解释 LangGraph，那就是：

> **LangGraph 是一个用"图结构"来编排 AI Agent 工作流的框架。**

听起来有点抽象？没关系，我们用大白话拆解一下。

---

## 什么是"图结构"？

先别想复杂了。"图"在这里不是指图片，而是数学里的"图"（Graph）——由**节点（Node）**和**边（Edge）**组成的结构。

你可以把它想象成：
- **节点**就是"做事的地方"——比如"调用 LLM"、"查询数据库"、"发邮件"
- **边**就是"从一个地方走到另一个地方的路"——决定"做完这件事，下一步做什么"

举个例子，假设你要做一个客服 Agent：

```
[用户输入问题] 
    ↓
[理解用户意图] 
    ↓
[判断：需要查数据库吗？]
    ├─ 需要 → [查数据库] → [生成回复]
    └─ 不需要 → [直接生成回复]
        ↓
[返回给用户]
```

这就是一个"图"。每个方框是一个节点，箭头是边。

---

## 什么是"工作流"？

工作流就是"一件事情要分几步做，每一步做什么"。

传统的程序是线性的：
```python
步骤1()
步骤2()
步骤3()
```

但 AI Agent 不一样——它需要**根据情况动态决定下一步做什么**。比如：
- LLM 说"我需要查天气"，那就去调用天气 API
- LLM 说"我需要搜索网页"，那就去调用搜索工具
- LLM 说"我已经有答案了"，那就结束

这种"动态决策"用传统的 if-else 写起来会非常乱。而用"图结构"来表达，就清晰多了。

---

## 为什么要用"图"？

你可能会问：为什么不直接写 Python 代码，非要搞个"图"出来？

因为 AI Agent 有几个特点，传统代码不好处理：

### 1. **循环执行**
Agent 经常需要"试错-修正-再试"：
```
[生成代码] → [运行代码] → 失败了？→ [修复代码] → [再运行] → ...
```

这是一个循环，不是简单的"从上到下"。用图结构，可以很自然地表达"从某个节点回到前面的节点"。

### 2. **条件分支**
Agent 需要根据 LLM 的输出，动态决定下一步：
- LLM 说调用工具 A → 走路径 A
- LLM 说调用工具 B → 走路径 B
- LLM 说不需要工具 → 直接结束

用图结构，可以用"条件边"来表达这种分支逻辑。

### 3. **状态管理**
Agent 需要在多个步骤之间传递信息：
- 节点1：LLM 生成了一个查询语句
- 节点2：拿这个查询语句去数据库查
- 节点3：拿查询结果让 LLM 生成回复

这些信息要怎么传递？LangGraph 提供了一个"状态（State）"机制，所有节点都可以读写这个共享的状态。

### 4. **人工介入**
有时候 Agent 需要暂停，等人类审批：
```
[Agent 想执行一个操作] → [暂停，问人类] → 人类说 OK → [继续执行]
```

图结构可以很方便地在某个节点"打断"，等人类输入后再"恢复"。

---

## 一个最简单的例子

用 LangGraph 构建一个最简单的 Agent，代码是这样的：

```python
from langgraph.graph import StateGraph, MessagesState, START, END

# 定义一个节点：调用 LLM
def call_llm(state: MessagesState):
    # 这里会调用 LLM，返回一条消息
    return {"messages": [{"role": "ai", "content": "你好！"}]}

# 构建图
graph = StateGraph(MessagesState)
graph.add_node("llm", call_llm)  # 添加一个节点
graph.add_edge(START, "llm")     # 从开始 → llm
graph.add_edge("llm", END)       # 从 llm → 结束

# 编译并运行
app = graph.compile()
result = app.invoke({"messages": [{"role": "user", "content": "你好"}]})
print(result)
```

这段代码做了什么？
1. 定义了一个节点 `call_llm`，它的工作是调用 LLM
2. 用 `StateGraph` 构建了一个图
3. 添加了一条路径：`START → llm → END`
4. 编译这个图，然后运行

就这么简单。

---

## 小结

LangGraph 用"图"来编排 AI Agent 的工作流，核心原因是：
- **循环执行**：Agent 需要来回试错
- **条件分支**：Agent 需要根据情况动态选择下一步
- **状态管理**：多个步骤之间需要传递信息
- **人工介入**：Agent 需要在某些节点暂停，等人类决策

用"图"来表达这些逻辑，比用传统的 if-else 清晰得多。
