# 10.2 架构分析：Kami Code 如何使用 LangGraph

## 整体架构

```
用户输入 (CLI)
    ↓
[Runtime 层]
    ↓
[deepagents_adapter.py] ← 封装 deepagents 的 Agent
    ↓
[deepagents (基于 LangGraph)]
    ↓
[LangGraph ReAct Agent]
    ├── model 节点：LLM 调用
    ├── tools 节点：工具执行
    └── input 节点：用户输入
    ↓
[message_stream.py] ← 解析 LangGraph 流式输出
    ↓
[usage.py] ← 追踪 Token 使用量
    ↓
CLI 输出
```

---

## 核心文件解读

### 1. `message_stream.py` — 流消息解析

这是最核心的文件——解析 LangGraph 的流式输出。

**LangGraph 的流式输出格式**：

```python
# LangGraph 的 stream_mode="messages" 返回的数据格式
(message, metadata)

# message: LangChain 的消息对象（AIMessageChunk、ToolMessage 等）
# metadata: 元数据字典，包含 "langgraph_node" 字段
```

**核心代码**：

```python
def _stream_node(chunk: Any) -> str:
    """从 chunk 中提取节点名"""
    if not isinstance(chunk, tuple) or len(chunk) < 2 or not isinstance(chunk[1], dict):
        return ""
    value = chunk[1].get("langgraph_node")
    return value.strip().lower() if isinstance(value, str) else ""
```

这个函数从 chunk 的 metadata 中提取 `langgraph_node` 字段——它告诉你这条消息来自哪个节点。

**节点类型**：

| `langgraph_node` 值 | 含义 |
|---------------------|------|
| `"model"` | LLM 生成的消息（assistant） |
| `"tools"` | 工具调用结果 |
| `"input"` | 用户输入回显 |

**消息过滤逻辑**：

```python
def assistant_text_from_stream_chunk(chunk):
    """只提取来自 model 节点的 assistant 文本"""
    node = _stream_node(chunk)
    
    if node != "model":
        return ""  # 不是 model 节点的，跳过
    
    message = chunk[0]
    if message.type != "ai":
        return ""  # 不是 assistant 消息，跳过
    
    return message.content
```

**关键洞察**：LangGraph 的流式输出中，所有节点的消息都混在一起——你需要通过 `langgraph_node` 来区分它们。Kami Code 只关心 `model` 节点的 assistant 消息，过滤掉 `tools` 和 `input` 的消息。

### 2. `usage.py` — Token 使用量追踪

**核心代码**：

```python
def usage_from_stream_chunk(chunk, *, model: str):
    """从流式 chunk 中提取 Token 使用量"""
    message = _stream_message(chunk)
    role = _message_role(message)
    
    # 只从 assistant 消息中提取
    if role == "assistant":
        return usage_from_message(message, model=model)
    
    # 或者从 model 节点的 unknown 消息中提取
    if role == "unknown" and _stream_node(chunk) == "model":
        return usage_from_message(message, model=model)
    
    return None
```

**关键洞察**：Token 使用量信息在 LLM 返回的消息对象中（`message.usage_metadata`），不是所有消息都有——只有 `model` 节点的 assistant 消息才有。

### 3. `deepagents_adapter.py` — Agent 适配器

**核心代码**：

```python
def stream_events(self, payload):
    """流式事件迭代器"""
    usage_accumulator = UsageAccumulator(model=self.model_profile.name)
    
    try:
        # 优先使用 messages stream mode
        for chunk in self._agent.stream(payload, stream_mode="messages"):
            usage_accumulator.observe(
                usage_from_stream_chunk(chunk, model=self.model_profile.name)
            )
            yield from self._message_stream_chunk_to_events(chunk)
    except TypeError:
        # 降级到 state stream mode
        for chunk in self._agent.stream(payload):
            usage_accumulator.observe(
                usage_from_stream_chunk(chunk, model=self.model_profile.name)
            )
            yield from self._state_stream_chunk_to_events(chunk)
```

**关键设计**：
1. **优先使用 `stream_mode="messages"`**：这是 LangGraph 的消息级流式输出，每个 token 都是一个 chunk
2. **降级到 state stream**：如果 Agent 不支持 messages mode，降级到状态级流式输出
3. **统一的事件接口**：不管底层用什么 stream mode，对外暴露统一的事件接口

---

### 4. `runtime/__init__.py` — Runtime 层

```python
def _iter_agent_stream_events(agent, payload):
    """Runtime 层的流式事件迭代"""
    
    # 优先使用 stream_events 适配器
    stream_events = getattr(agent, "stream_events", None)
    if callable(stream_events):
        for event in stream_events(payload):
            yield event
        return
    
    # 尝试 messages stream mode
    try:
        for chunk in agent.stream(payload, stream_mode="messages"):
            for event in _message_stream_chunk_to_events(chunk):
                yield event
    except TypeError:
        # 降级到 state stream
        yield from _iter_state_stream_events(agent, payload)
```

**三级降级策略**：
1. `agent.stream_events()` — 适配器级事件流
2. `agent.stream(stream_mode="messages")` — LangGraph 消息级流
3. `agent.stream()` — LangGraph 状态级流

---

## 小结

Kami Code 的架构设计体现了几个重要原则：

1. **适配器模式**：通过 `deepagents_adapter.py` 封装底层框架的差异
2. **降级策略**：优先用高级 API，失败时降级到低级 API
3. **统一接口**：对外暴露统一的事件接口，不管底层用什么
4. **流式处理**：全程流式处理，用户体验好

这些设计模式在你构建自己的 Agent 应用时，非常值得借鉴。
