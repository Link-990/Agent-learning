# 4.2 Middleware 的生命周期

Middleware 可以在 Agent 执行的多个阶段进行拦截。

---

## Agent 循环的阶段

```
1. [before_model] → Middleware 可以修改 LLM 的输入
       ↓
2. LLM 调用
       ↓
3. [after_model] → Middleware 可以修改 LLM 的输出
       ↓
4. 判断：需要工具吗？
       ↓
5. [before_tool] → Middleware 可以修改工具参数或阻止执行
       ↓
6. 工具执行
       ↓
7. [after_tool] → Middleware 可以修改工具结果
       ↓
8. 回到步骤 1（循环）
```

---

## wrap_model_call：拦截模型调用

这是最常用的拦截点——在 LLM 调用前后做文章。

```python
class MyMiddleware(AgentMiddleware):
    def wrap_model_call(self, request, handler):
        # 调用前：可以修改 request
        print(f"即将调用 LLM，工具数：{len(request.tools)}")
        
        # 调用 LLM
        response = handler(request)
        
        # 调用后：可以修改 response
        print(f"LLM 返回完成")
        
        return response
```

### request 对象

```python
request.messages    # 消息列表
request.tools       # 可用工具列表
request.state       # Agent 状态
request.runtime     # 运行时上下文

# 修改 request
new_request = request.override(
    tools=filtered_tools,
    messages=modified_messages
)
```

---

## 拦截工具执行

```python
class ToolFilterMiddleware(AgentMiddleware):
    def wrap_tool_call(self, tool_request, handler):
        tool_name = tool_request.tool_name
        
        # 阻止危险工具
        if tool_name == "delete_file":
            return ToolResponse(content="权限不足，拒绝执行")
        
        # 其他工具正常执行
        return handler(tool_request)
```

---

## 小结

Middleware 的拦截点：
- `wrap_model_call`：拦截 LLM 调用（最常用）
- `wrap_tool_call`：拦截工具执行

`request` 对象提供了访问和修改 Agent 状态的接口。
