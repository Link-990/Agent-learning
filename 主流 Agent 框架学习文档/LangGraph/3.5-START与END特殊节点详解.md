# 3.5 START 与 END——特殊节点详解

在 LangGraph 中，`START` 和 `END` 是两个特殊的节点——它们不是你定义的函数，而是系统内置的"标记"。

理解它们的作用和用法，是构建清晰工作流的关键。

---

## START：图的入口

### START 是什么？

`START` 是一个特殊的标记，表示"从这里开始执行"。

```python
from langgraph.graph import START

graph.add_edge(START, "first_node")
```

这表示：当图开始执行时，第一个执行的节点是 `first_node`。

### START 不是一个函数

重要的是：**START 本身不执行任何逻辑**。它只是一个"起点标记"。

你不能这样写：

```python
graph.add_node(START, some_func)  # 错误！START 不是节点
```

### START 只能作为边的起点

合法用法：

```python
graph.add_edge(START, "node_a")  # ✅ 正确
```

不合法用法：

```python
graph.add_edge("node_a", START)  # ❌ 错误！不能连回 START
```

---

## END：图的出口

### END 是什么？

`END` 是一个特殊的标记，表示"到这里结束"。

```python
from langgraph.graph import END

graph.add_edge("last_node", END)
```

这表示：执行完 `last_node`，图的执行就结束了。

### END 也不是一个函数

和 START 一样，**END 本身不执行任何逻辑**。

你不能这样写：

```python
graph.add_node(END, some_func)  # 错误！END 不是节点
```

### END 只能作为边的终点

合法用法：

```python
graph.add_edge("node_z", END)  # ✅ 正确
```

不合法用法：

```python
graph.add_edge(END, "node_a")  # ❌ 错误！不能从 END 出发
```

---

## 为什么需要 START 和 END？

### 没有 START 和 END 的问题

假设没有这两个标记，你会怎么表示"从哪开始"和"到哪结束"？

可能是这样：

```python
graph.set_entry_point("first_node")  # 设置入口
graph.set_exit_point("last_node")    # 设置出口
```

这样可以，但不够直观。

### 有了 START 和 END

```python
graph.add_edge(START, "first_node")
graph.add_edge("last_node", END)
```

这样一看就懂："从 START 到 first_node，从 last_node 到 END"。

**更重要的是**：用边来表示入口/出口，和其他边保持一致，更符合"图"的思维。

---

## 多个入口和出口

### 多个入口：从 START 连到多个节点

```python
graph.add_edge(START, "node_a")
graph.add_edge(START, "node_b")
```

这表示：`node_a` 和 `node_b` **并行执行**。

流程图：

```
      ┌→ node_a
START 
      └→ node_b
```

### 多个出口：多个节点连到 END

```python
graph.add_edge("node_x", END)
graph.add_edge("node_y", END)
graph.add_edge("node_z", END)
```

这表示：`node_x`、`node_y`、`node_z` 中任何一个执行完，都可以结束。

流程图：

```
node_x →
node_y → END
node_z →
```

## 实战示例 1：线性流程

```python
from langgraph.graph import StateGraph, START, END
from typing import TypedDict

class State(TypedDict):
    value: int

def step_1(state):
    return {"value": state["value"] + 1}

def step_2(state):
    return {"value": state["value"] * 2}

graph = StateGraph(State)
graph.add_node("step_1", step_1)
graph.add_node("step_2", step_2)

graph.add_edge(START, "step_1")
graph.add_edge("step_1", "step_2")
graph.add_edge("step_2", END)

app = graph.compile()
result = app.invoke({"value": 0})
print(result)  # {"value": 2}
# 0 + 1 = 1 → 1 * 2 = 2
```

## 实战示例 2：条件路由到 END

```python
from langgraph.graph import StateGraph, START, END
from typing import TypedDict

class State(TypedDict):
    value: int

def process(state):
    return {"value": state["value"] + 10}

def should_continue(state):
    if state["value"] < 50:
        return "continue"
    else:
        return "end"

graph = StateGraph(State)
graph.add_node("process", process)

graph.add_edge(START, "process")
graph.add_conditional_edges(
    "process",
    should_continue,
    {
        "continue": "process",  # 回到自己，循环
        "end": END
    }
)

app = graph.compile()
result = app.invoke({"value": 0})
print(result)  # {"value": 50}
# 0 + 10 = 10 + 10 = 20 + 10 = 30 + 10 = 40 + 10 = 50（停止）
```

流程图：

```
START → process ⟲ (value < 50)
         ↓
        END (value >= 50)
```

## 实战示例 3：并行入口

```python
from langgraph.graph import StateGraph, START, END
from typing import TypedDict

class State(TypedDict):
    result_a: str
    result_b: str

def task_a(state):
    return {"result_a": "A 完成"}

def task_b(state):
    return {"result_b": "B 完成"}

def merge(state):
    print(f"{state['result_a']} + {state['result_b']}")
    return {}

graph = StateGraph(State)
graph.add_node("task_a", task_a)
graph.add_node("task_b", task_b)
graph.add_node("merge", merge)

# 并行入口
graph.add_edge(START, "task_a")
graph.add_edge(START, "task_b")

# 汇总
graph.add_edge("task_a", "merge")
graph.add_edge("task_b", "merge")
graph.add_edge("merge", END)

app = graph.compile()
app.invoke({"result_a": "", "result_b": ""})
# 输出：A 完成 + B 完成
```

## 常见错误

### 错误 1：忘记从 START 出发

```python
graph.add_node("node_a", func_a)
graph.add_edge("node_a", END)
# 忘了：graph.add_edge(START, "node_a")

app = graph.compile()  # 报错！
```

报错：`Graph must have at least one edge from START`

**解决**：必须有至少一条从 START 出发的边。

### 错误 2：节点没有连到 END

```python
graph.add_node("node_z", func_z)
graph.add_edge(START, "node_z")
# 忘了：graph.add_edge("node_z", END)

app = graph.compile()  # 报错！
```

报错：`Node 'node_z' has no outgoing edges`

**解决**：每个"叶子节点"必须连到 END 或其他节点。

### 错误 3：尝试连回 START

```python
graph.add_edge("node_a", START)  # ❌ 不允许
```

报错：`Cannot add edge to START`

**解决**：START 只能作为起点，不能作为终点。

### 错误 4：尝试从 END 出发

```python
graph.add_edge(END, "node_b")  # ❌ 不允许
```

报错：`Cannot add edge from END`

**解决**：END 只能作为终点，不能作为起点。

## START 和 END 的本质

在 LangGraph 内部，START 和 END 其实就是两个特殊的字符串常量：

```python
START = "__start__"
END = "__end__"
```

它们的作用是：
- **START**：标记图的入口
- **END**：标记图的出口

你可以把它们想象成"虚拟节点"——不执行逻辑，只起标记作用。

---

## 小结

- **START**：图的入口标记，表示"从这里开始"
  - 用法：`graph.add_edge(START, "first_node")`
  - 不是函数，不能作为 add_node 的参数
  - 只能作为边的起点
  
- **END**：图的出口标记，表示"到这里结束"
  - 用法：`graph.add_edge("last_node", END)`
  - 不是函数，不能作为 add_node 的参数
  - 只能作为边的终点

- **多入口/多出口**：
  - 多条从 START 出发的边 → 并行入口
  - 多条到 END 的边 → 多个出口

- **必须有**：
  - 至少一条从 START 出发的边
  - 每个节点都要有出边（连到其他节点或 END）

理解了 START 和 END，你就掌握了图的"边界"——知道从哪开始，到哪结束。
