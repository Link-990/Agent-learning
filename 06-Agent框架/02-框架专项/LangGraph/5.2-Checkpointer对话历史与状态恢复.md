# 5.2 Checkpointer：对话历史与状态恢复

Checkpointer 是 LangGraph 的核心机制——它在每个节点执行后，自动保存完整的状态快照。

这一节我们详细学习 Checkpointer 的工作原理和使用方法。

---

## Checkpointer 是什么？

**Checkpointer** 是一个"状态快照管理器"。

每次执行到一个节点后，Checkpointer 会：
1. 保存当前的完整状态（State）
2. 生成一个 `checkpoint_id`（唯一标识）
3. 把这个 checkpoint 存储起来（内存或数据库）

下次执行时，LangGraph 会：
1. 加载上一次的 checkpoint
2. 从那个状态继续执行

---

## 基本用法

### 1. 创建 Checkpointer

```python
from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()
```

### 2. 绑定到 Graph

```python
from langgraph.graph import StateGraph, MessagesState, START, END

graph = StateGraph(MessagesState)
# ... 添加节点和边 ...

app = graph.compile(checkpointer=checkpointer)
```

### 3. 使用 thread_id

```python
result = app.invoke(
    {"messages": [{"role": "user", "content": "你好"}]},
    config={"configurable": {"thread_id": "thread_1"}}
)
```

**关键点**：必须提供 `thread_id`，Checkpointer 才能知道保存/加载哪个对话的状态。

---

## thread_id：对话的唯一标识

`thread_id` 是一个字符串，用于标识一个"对话线程"。

### 示例

```python
# 用户 A 的对话
app.invoke(input1, config={"configurable": {"thread_id": "user_A"}})

# 用户 B 的对话
app.invoke(input2, config={"configurable": {"thread_id": "user_B"}})

# 用户 A 继续对话
app.invoke(input3, config={"configurable": {"thread_id": "user_A"}})
```

每个 `thread_id` 有自己的 checkpoint 链，互不干扰。

### thread_id 的命名

```python
# 好的命名
"user_123"
"session_abc"
"conversation_2024-01-15_user_alice"

# 不好的命名
"1"  # 太短，容易混淆
"thread"  # 不区分用户
```

---

## Checkpoint 的结构

每个 checkpoint 包含：

```python
{
    "v": 1,                          # 版本号
    "id": "checkpoint_uuid",         # checkpoint 的唯一 ID
    "ts": "2024-01-15T10:30:00Z",   # 时间戳
    "channel_values": {              # 状态值
        "messages": [...],
        "other_state": ...
    },
    "channel_versions": {...},       # 每个 channel 的版本号
    "versions_seen": {...}           # 已看到的版本
}
```

## 查看 Checkpoint 历史

### 获取当前状态

```python
state = app.get_state(config={"configurable": {"thread_id": "thread_1"}})

print(state.values)        # 当前状态值
print(state.next)          # 下一步要执行的节点
print(state.config)        # 配置（包含 checkpoint_id）
print(state.metadata)      # 元数据
```

### 获取历史状态

```python
# 获取所有历史 checkpoint
history = list(app.get_state_history(
    config={"configurable": {"thread_id": "thread_1"}}
))

for state in history:
    print(f"Checkpoint ID: {state.config['configurable']['checkpoint_id']}")
    print(f"时间: {state.metadata['ts']}")
    print(f"状态: {state.values}")
    print("---")
```

输出：

```
Checkpoint ID: checkpoint_123
时间: 2024-01-15T10:30:00Z
状态: {'messages': [{'role': 'user', 'content': '你好'}]}
---
Checkpoint ID: checkpoint_122
时间: 2024-01-15T10:29:00Z
状态: {'messages': []}
---
```

## 状态恢复

### 从最新状态继续

```python
# 第一次调用
app.invoke(input1, config={"configurable": {"thread_id": "1"}})

# 第二次调用：自动加载上一次的状态
app.invoke(input2, config={"configurable": {"thread_id": "1"}})
```

### 从指定 checkpoint 恢复

```python
# 获取历史状态
history = list(app.get_state_history(config={"configurable": {"thread_id": "1"}}))

# 选择第 3 个 checkpoint
old_state = history[2]

# 从那个状态继续执行
result = app.invoke(
    None,  # 不传新输入，从历史状态继续
    config=old_state.config  # 使用历史状态的 config
)
```

## 实战示例：一个有记忆的对话机器人

```python
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.checkpoint.memory import MemorySaver
from langchain_openai import ChatOpenAI
from dotenv import load_dotenv

load_dotenv()

# 创建 LLM
llm = ChatOpenAI(model="gpt-4o-mini")

# 定义节点
def chat(state: MessagesState):
    response = llm.invoke(state["messages"])
    return {"messages": [response]}

# 构建图
graph = StateGraph(MessagesState)
graph.add_node("chat", chat)
graph.add_edge(START, "chat")
graph.add_edge("chat", END)

# 添加 checkpointer
checkpointer = MemorySaver()
app = graph.compile(checkpointer=checkpointer)

# 对话函数
def chat_with_agent(user_input: str, thread_id: str):
    result = app.invoke(
        {"messages": [{"role": "user", "content": user_input}]},
        config={"configurable": {"thread_id": thread_id}}
    )
    return result["messages"][-1].content

# 测试
if __name__ == "__main__":
    thread_id = "user_alice"
    
    # 第一轮对话
    response = chat_with_agent("我叫 Alice，我喜欢编程", thread_id)
    print(f"AI: {response}")
    
    # 第二轮对话
    response = chat_with_agent("我喜欢什么？", thread_id)
    print(f"AI: {response}")
    
    # 第三轮对话
    response = chat_with_agent("我叫什么名字？", thread_id)
    print(f"AI: {response}")
    
    # 查看历史状态
    print("\n=== 历史状态 ===")
    history = list(app.get_state_history(
        config={"configurable": {"thread_id": thread_id}}
    ))
    print(f"共有 {len(history)} 个 checkpoint")
```

输出：

```
AI: 很高兴认识你，Alice！编程是一项非常有趣和有用的技能。你在学习哪些编程语言或技术呢？
AI: 你喜欢编程。
AI: 你叫 Alice。

=== 历史状态 ===
共有 7 个 checkpoint
```

## Checkpoint 的生命周期

### 何时创建 checkpoint？

- **每个节点执行后**：会创建一个新的 checkpoint
- **START 和 END**：也会创建 checkpoint

### 一次执行会产生多少个 checkpoint？

假设有 3 个节点：`A → B → C`

一次执行会产生：
1. START checkpoint
2. A 节点执行后 checkpoint
3. B 节点执行后 checkpoint
4. C 节点执行后 checkpoint
5. END checkpoint

**总共 5 个 checkpoint**。

## 更新状态

有时候你需要手动修改状态（比如修正 AI 的错误回复）。

### 使用 update_state

```python
# 获取当前状态
state = app.get_state(config={"configurable": {"thread_id": "1"}})

# 修改状态
app.update_state(
    config={"configurable": {"thread_id": "1"}},
    values={"messages": [{"role": "assistant", "content": "修正后的回复"}]},
    as_node="chat"  # 指定是哪个节点的输出
)

# 继续执行
result = app.invoke(None, config={"configurable": {"thread_id": "1"}})
```

## Checkpoint 的清理

Checkpoint 会累积，占用存储空间。可以手动清理：

```python
# 获取历史
history = list(app.get_state_history(
    config={"configurable": {"thread_id": "thread_1"}}
))

# 只保留最近 10 个
if len(history) > 10:
    for old_state in history[10:]:
        # 删除旧的 checkpoint（具体 API 取决于 checkpointer 实现）
        pass
```

（注意：MemorySaver 在程序退出后会自动清理，持久化的 Checkpointer 需要手动清理）

## Checkpointer 的类型

LangGraph 提供多种 Checkpointer 实现：

| Checkpointer | 存储位置 | 持久化 | 适用场景 |
|--------------|---------|-------|---------|
| MemorySaver | 内存 | ❌ 程序退出后丢失 | 开发、测试 |
| SqliteSaver | SQLite 数据库 | ✅ 持久化 | 小型应用 |
| PostgresSaver | PostgreSQL 数据库 | ✅ 持久化 | 生产环境 |
| RedisSaver | Redis | ✅ 持久化 | 高并发 |
| AsyncSqliteSaver | SQLite（异步） | ✅ 持久化 | 异步应用 |

下一节我们会详细学习 MemorySaver 和 SqliteSaver。

## 小结

Checkpointer 的核心概念：

1. **自动保存状态**：每个节点执行后自动创建 checkpoint
2. **thread_id**：用于隔离不同对话的状态
3. **checkpoint_id**：每个 checkpoint 的唯一标识
4. **状态恢复**：下次执行时自动加载上一次的状态
5. **历史回溯**：可以查看和恢复到任意历史状态

使用 Checkpointer 的步骤：
1. 创建 checkpointer（如 `MemorySaver()`）
2. 绑定到 graph（`compile(checkpointer=...)`）
3. 调用时传递 `thread_id`
