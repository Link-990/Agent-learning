# 2.5 工具调用（Tool Calling）

工具调用（Tool Calling）是 Agent 系统的核心机制——LLM 根据用户请求，自主决定调用哪个工具。

这一节我们深入理解工具调用的完整流程。

---

## 工具调用的完整流程

```
用户输入
    ↓
LLM 看到：用户消息 + 可用工具列表
    ↓
LLM 决定：
    ├─ 不需要工具 → 直接回复
    └─ 需要工具 → 返回 tool_calls
        ↓
    执行工具 → 得到结果
        ↓
    ToolMessage 喂给 LLM
        ↓
    LLM 再次判断：
        ├─ 还需要工具 → 继续调用（循环）
        └─ 不需要了 → 生成最终回复
            ↓
        返回给用户
```

---

## tool_calls 的结构

当 LLM 决定调用工具时，返回的 `AIMessage` 会包含 `tool_calls`：

```python
response = llm_with_tools.invoke([
    HumanMessage(content="北京天气怎么样？")
])

# response.tool_calls 的结构
[
    {
        "name": "get_weather",           # 工具名
        "args": {"city": "北京"},        # 工具参数
        "id": "call_abc123"              # 唯一 ID
    }
]
```

### 关键点

- `name`：要调用的工具名
- `args`：传给工具的参数（字典）
- `id`：每次工具调用的唯一标识，用于关联 ToolMessage

---

## 多个工具调用

LLM 可以同时调用多个工具：

```python
response = llm_with_tools.invoke([
    HumanMessage(content="北京和上海今天天气怎么样？")
])

# tool_calls 有多个
[
    {"name": "get_weather", "args": {"city": "北京"}, "id": "call_1"},
    {"name": "get_weather", "args": {"city": "上海"}, "id": "call_2"}
]
```

## 工具调用循环

`create_agent()` 自动处理工具调用循环：

```python
from langchain.agents import create_agent

@tool
def search(query: str) -> str:
    """搜索信息"""
    return f"搜索结果：{query}"

@tool
def summarize(text: str) -> str:
    """总结文本"""
    return f"总结：{text[:50]}..."

agent = create_agent(
    model="openai:gpt-4o-mini",
    tools=[search, summarize],
    system_prompt="你是一个研究助手"
)

# Agent 会自动：
# 1. 调用 search 搜索
# 2. 拿到结果
# 3. 调用 summarize 总结
# 4. 返回最终结果
result = agent.invoke(
    {"messages": [{"role": "user", "content": "搜索 AI 最新进展并总结"}]}
)
```

## 判断是否需要工具

```python
def should_continue(state):
    last_message = state["messages"][-1]
    
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        return "tools"  # 需要工具
    else:
        return "end"    # 不需要工具，结束
```

## 工具调用的错误处理

```python
@tool
def risky_tool(x: int) -> str:
    """一个可能出错的工具"""
    if x < 0:
        raise ValueError("x 不能为负数")
    return str(x * 2)

# 如果工具抛出异常，异常信息会作为 ToolMessage 返回给 LLM
# LLM 可以选择重试或换一种方式
```

## Kami Code 中的工具调用

Kami Code 的工具调用循环由 `deepagents` 框架管理。它的底层就是一个 ReAct 模式的 LangGraph 图：

```
input → model → (需要工具?) → tools → model → ...
                    ↓ 不需要
                   END
```

Kami Code 通过 `langgraph_node` 元数据区分：
- `"model"` 节点：LLM 的回复
- `"tools"` 节点：工具的执行结果

---

## 小结

工具调用的核心：
1. LLM 看到工具列表，决定是否需要调用
2. 如果需要，返回 `tool_calls`（name + args + id）
3. 你的代码执行工具，返回 `ToolMessage`
4. LLM 根据工具结果继续判断
5. 循环，直到 LLM 认为可以回复用户

`create_agent()` 自动处理整个循环——你只需要定义工具和 system_prompt。
