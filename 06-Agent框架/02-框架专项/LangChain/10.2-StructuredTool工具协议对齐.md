# 10.2 StructuredTool：工具协议对齐

Kami Code 有自己的工具规范（`ToolSpec`），但为了让工具能被 LangChain 生态的 LLM 调用，需要转换成 `StructuredTool`。

---

## 核心代码

```python
# kamiagent/tools/registry.py
from langchain_core.tools import StructuredTool

class ToolRegistry:
    def as_structured_tool_list(self) -> list[StructuredTool]:
        return [
            StructuredTool.from_function(
                func=spec.handler,
                name=spec.name,
                description=spec.description,
                args_schema=spec.input_schema,
                infer_schema=False,
                metadata={
                    "public_name": spec.name,
                    "source": spec.source,
                    "search_hint": spec.search_hint,
                    "defer_loading": spec.defer_loading,
                    "is_read_only": spec.is_read_only,
                    "max_result_size_chars": spec.max_result_size_chars,
                },
            )
            for spec in self.list_specs()
        ]
```

---

## 解读

1. **`from_function`**：把函数转成 StructuredTool
2. **`args_schema`**：用 Pydantic Schema 定义参数
3. **`infer_schema=False`**：不从函数签名推断，用 `args_schema` 指定的
4. **`metadata`**：附加自定义元数据
   - `defer_loading`：是否延迟加载
   - `is_read_only`：是否只读
   - `search_hint`：搜索提示

这些 metadata 不会被 LLM 看到，但可以被 Middleware 用来做过滤。

---

## 设计亮点

- **两层工具系统**：内部 ToolSpec（完整信息） → 外部 StructuredTool（LLM 可见的接口）
- **metadata 扩展**：在不改变 LangChain 接口的情况下，携带项目特有的信息
