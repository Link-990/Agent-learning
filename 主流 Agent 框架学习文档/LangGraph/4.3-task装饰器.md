# 4.3 @task 装饰器——定义独立任务

如果说 `@entrypoint` 是工作流的"入口"，那么 `@task` 就是工作流里的"工作单元"。

用 `@task` 装饰的函数，会被 LangGraph 当作一个独立的"任务节点"——它可以：
- 被 checkpointer 记录
- 被 interrupt 暂停
- 被流式输出捕获

这一节我们学习 `@task` 的用法。

---

## 为什么需要 @task？

### 没有 @task 的问题

```python
@entrypoint
def workflow(topic: str) -> str:
    # 步骤 1
    outline = generate_outline(topic)
    
    # 步骤 2
    essay = write_essay(outline)
    
    # 步骤 3
    final = polish(essay)
    
    return final
```

这个工作流看起来有 3 个步骤，但对 LangGraph 来说，**它只是一个节点**——因为 `generate_outline`、`write_essay`、`polish` 都是普通函数调用。

结果：
- 不能在 `generate_outline` 和 `write_essay` 之间暂停
- 不能单独看到每个步骤的输出
- checkpointer 只能保存整个 workflow 的状态

### 用 @task 解决

```python
from langgraph.func import entrypoint, task

@task
def generate_outline(topic: str) -> str:
    return f"{topic} 的大纲..."

@task
def write_essay(outline: str) -> str:
    return f"根据 {outline} 写的文章..."

@task
def polish(essay: str) -> str:
    return f"润色后的文章：{essay}"

@entrypoint(checkpointer=MemorySaver())
def workflow(topic: str) -> str:
    outline = generate_outline(topic)
    essay = write_essay(outline)
    final = polish(essay)
    return final
```

现在，LangGraph 会把它编译成 3 个节点：
- `generate_outline` 节点
- `write_essay` 节点
- `polish` 节点

每个节点可以独立追踪、暂停、恢复。

## @task 的基本用法

### 定义一个 task

```python
from langgraph.func import task

@task
def my_task(input: str) -> str:
    # 任务逻辑
    result = input.upper()
    return result
```

### 在 entrypoint 里调用

```python
@entrypoint
def workflow(input: str) -> str:
    result = my_task(input)
    return result
```

### 调用方式

task 函数有两种调用方式：

#### 1. 同步调用（阻塞等待结果）

```python
result = my_task(input)
```

#### 2. 异步调用（获取"未来"对象）

```python
future = my_task.submit(input)
# 做其他事情...
result = future.result()  # 等待结果
```

---

## task 的可注入参数

和 entrypoint 一样，task 也支持可注入参数：

### 1. previous（上一步的结果）

```python
@task
def step2(input: str, previous) -> str:
    # previous 是上一个 task 的返回值
    return f"{previous} -> {input}"
```

### 2. store（长期记忆）

```python
@task
def save_to_memory(user_id: str, data: str, store):
    store.put(("user", user_id), "memory", data)
```

### 3. writer（流式输出）

```python
@task
def long_task(input: str, writer):
    writer.write("开始处理...")
    result = process(input)
    writer.write("处理完成")
    return result
```

### 4. config（运行时配置）

```python
@task
def my_task(input: str, config):
    thread_id = config.get("configurable", {}).get("thread_id")
    return f"处理 {input}，线程 {thread_id}"
```

---

## task 的并行执行

task 的一个强大特性是：**可以并行执行**。

### 示例：并行调用多个 task

```python
from langgraph.func import entrypoint, task

@task
def fetch_data_a() -> str:
    # 模拟耗时操作
    time.sleep(2)
    return "数据 A"

@task
def fetch_data_b() -> str:
    time.sleep(2)
    return "数据 B"

@task
def merge(a: str, b: str) -> str:
    return f"{a} + {b}"

@entrypoint
def workflow() -> str:
    # 提交两个并行任务
    future_a = fetch_data_a.submit()
    future_b = fetch_data_b.submit()
    
    # 等待结果
    a = future_a.result()
    b = future_b.result()
    
    # 合并
    result = merge(a, b)
    return result

# 执行时间 ~2 秒（不是 4 秒），因为 a 和 b 并行
result = workflow()
print(result)  # "数据 A + 数据 B"
```

## task 与 interrupt

可以在 entrypoint 里指定在哪个 task 之前/之后暂停：

```python
from langgraph.func import entrypoint, task
from langgraph.checkpoint.memory import MemorySaver

@task
def generate_plan(topic: str) -> str:
    return f"计划：{topic}"

@task
def execute_plan(plan: str) -> str:
    return f"执行：{plan}"

@entrypoint(
    checkpointer=MemorySaver(),
    interrupt_after=["generate_plan"]  # 在 generate_plan 后暂停
)
def workflow(topic: str) -> str:
    plan = generate_plan(topic)
    # 这里会暂停，等待人工审批
    result = execute_plan(plan)
    return result

# 第一次调用：会在 generate_plan 后暂停
state = workflow.invoke("建设大楼", config={"thread_id": "1"})

# 人工审批后，恢复执行
from langgraph.types import Command
result = workflow.invoke(Command(resume=None), config={"thread_id": "1"})
print(result)
```

## task 的命名

task 函数的名字很重要——它会作为节点名出现在图里、日志里、interrupt 配置里。

### 好的命名

```python
@task
def fetch_user_data(user_id: str) -> dict:
    ...

@task
def calculate_score(data: dict) -> float:
    ...

@task
def send_notification(score: float) -> None:
    ...
```

### 不好的命名

```python
@task
def task1(input):  # 太泛化
    ...

@task
def do_stuff(x):  # 不知道做什么
    ...
```

---

## task 的返回值类型

task 应该有明确的返回值类型标注：

```python
@task
def my_task(input: str) -> dict:
    return {"result": input.upper()}
```

这样：
- IDE 可以做类型检查
- 其他开发者一眼看出返回什么
- LangGraph 可以更好地优化执行

## 实战示例：一个多步骤的数据处理流程

```python
from langgraph.func import entrypoint, task
from typing import List, Dict

@task
def load_data(file_path: str) -> List[Dict]:
    """加载数据"""
    # 模拟加载
    return [{"id": 1, "value": 10}, {"id": 2, "value": 20}]

@task
def clean_data(data: List[Dict]) -> List[Dict]:
    """清洗数据"""
    return [item for item in data if item["value"] > 0]

@task
def transform_data(data: List[Dict]) -> List[Dict]:
    """转换数据"""
    return [{"id": item["id"], "value": item["value"] * 2} for item in data]

@task
def save_data(data: List[Dict], output_path: str) -> str:
    """保存数据"""
    # 模拟保存
    return f"已保存 {len(data)} 条数据到 {output_path}"

@entrypoint
def data_pipeline(input_path: str, output_path: str) -> str:
    # 1. 加载
    raw_data = load_data(input_path)
    
    # 2. 清洗
    clean = clean_data(raw_data)
    
    # 3. 转换
    transformed = transform_data(clean)
    
    # 4. 保存
    result = save_data(transformed, output_path)
    
    return result

# 执行
result = data_pipeline("input.csv", "output.csv")
print(result)
```

## task 的错误处理

如果 task 抛出异常，整个工作流会停止：

```python
@task
def risky_task(value: int) -> int:
    if value < 0:
        raise ValueError("值不能为负数")
    return value * 2

@entrypoint
def workflow(value: int) -> int:
    try:
        result = risky_task(value)
        return result
    except ValueError as e:
        # 捕获异常，返回默认值
        return 0

result = workflow(-5)
print(result)  # 0
```

## task 与 StateGraph 节点的对比

| 特性 | StateGraph 节点 | @task |
|------|----------------|-------|
| 定义方式 | 普通函数 + add_node | @task 装饰器 |
| 参数 | 接收 State 字典 | 接收普通参数 |
| 返回值 | State 更新字典 | 普通返回值 |
| 调用方式 | 通过图执行 | 像普通函数调用 |
| 并行执行 | 需要显式设计 | 用 .submit() |

## 常见错误

### 错误 1：在 task 外调用 task

```python
@task
def my_task(input: str) -> str:
    return input.upper()

# 在 entrypoint 外调用
result = my_task("hello")  # 可能出错！
```

**解决**：task 应该在 entrypoint 内部调用，或者用 `.invoke()` 调用。

### 错误 2：task 之间共享可变对象

```python
shared_list = []

@task
def task_a():
    shared_list.append("a")

@task
def task_b():
    shared_list.append("b")

@entrypoint
def workflow():
    task_a()
    task_b()
    return shared_list
```

这可能导致竞态条件（如果 task 并行执行）。

**解决**：task 之间通过返回值传递数据，不要共享可变对象。

---

## 小结

`@task` 的作用：
- 把函数变成一个独立的"任务节点"
- 可以被 checkpointer 记录
- 可以被 interrupt 暂停
- 可以并行执行（`.submit()`）

可注入参数：
- `previous`：上一步结果
- `store`：长期记忆
- `writer`：流式输出
- `config`：运行时配置

最佳实践：
- 给 task 起清晰的名字
- 标注返回值类型
- task 之间通过返回值传递数据

掌握了 `@task`，你就能用 Functional API 构建多步骤的工作流，并且每一步都是独立可追踪的。
