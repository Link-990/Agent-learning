# 7.1 为什么需要流式输出？

让我们先通过对比，直观感受流式输出的价值。

---

## 没有流式输出的体验

```python
from langgraph.graph import StateGraph, MessagesState, START, END
from langchain_openai import ChatOpenAI
import time

llm = ChatOpenAI(model="gpt-4o-mini")

def slow_task(state):
    """模拟一个耗时的任务"""
    time.sleep(5)  # 模拟 5 秒的处理
    return {"messages": [{"role": "assistant", "content": "任务完成！"}]}

graph = StateGraph(MessagesState)
graph.add_node("task", slow_task)
graph.add_edge(START, "task")
graph.add_edge("task", END)

app = graph.compile()

# 调用
print("开始执行...")
result = app.invoke({"messages": []})
print(f"执行完成：{result['messages'][-1]['content']}")
```

输出：

```
开始执行...
（等待 5 秒）
执行完成：任务完成！
```

**用户体验**：等了 5 秒，没有任何反馈。用户不知道 Agent 是在运行还是卡住了。

---

## 有流式输出的体验

```python
def slow_task_with_stream(state, writer):
    """带流式输出的任务"""
    writer.write("🔍 正在分析数据...")
    time.sleep(2)
    
    writer.write("📊 生成报告...")
    time.sleep(2)
    
    writer.write("✅ 完成！")
    time.sleep(1)
    
    return {"messages": [{"role": "assistant", "content": "任务完成！"}]}

graph = StateGraph(MessagesState)
graph.add_node("task", slow_task_with_stream)
graph.add_edge(START, "task")
graph.add_edge("task", END)

app = graph.compile()

# 流式调用
print("开始执行...")
for event in app.stream({"messages": []}):
    if "messages" in event.get("task", {}):
        print(event["task"]["messages"][0])
print("执行完成")
```

输出：

```
开始执行...
🔍 正在分析数据...
（2 秒后）
📊 生成报告...
（2 秒后）
✅ 完成！
（1 秒后）
执行完成
```

**用户体验**：实时看到 Agent 的进度，知道它在做什么，体验好很多。

---

## 流式输出的使用场景

### 场景 1：对话 Agent

用户问了一个问题，LLM 需要 3 秒生成回答。

**没有流式**：
```
用户：你好
（等待 3 秒）
AI：你好！很高兴认识你。
```

**有流式**：
```
用户：你好
（实时）
AI：你...好...！...很...高...兴...认...识...你...。
```

（像 ChatGPT 一样，一个字一个字"打出来"）

### 场景 2：多步骤任务

Agent 要完成一个多步骤任务：

**没有流式**：
```
用户：帮我分析销售数据
（等待 30 秒）
AI：分析完成，报告如下：...
```

**有流式**：
```
用户：帮我分析销售数据
AI：📥 正在加载数据...
AI：📊 正在分析 2023 年 Q1 数据...
AI：📊 正在分析 2023 年 Q2 数据...
AI：📊 正在生成图表...
AI：✅ 分析完成，报告如下：...
```

### 场景 3：调试和监控

开发者想看 Agent 的每一步执行：

**没有流式**：
```python
result = app.invoke(input)
print(result)  # 只能看到最终结果
```

**有流式**：
```python
for event in app.stream(input):
    node_name = list(event.keys())[0]
    print(f"执行节点：{node_name}")
    print(f"输出：{event[node_name]}")
```

---

## LangGraph 的流式 API

LangGraph 提供两种流式 API：

### 1. stream()

返回每个节点执行后的状态更新。

```python
for event in app.stream(input):
    # event 是一个字典，key 是节点名，value 是该节点的输出
    print(event)
```

### 2. stream_events()

返回更细粒度的事件流，包括：
- 节点开始执行
- LLM 生成的每个 token
- 工具调用
- 节点执行完成

```python
for event in app.stream_events(input, version="v2"):
    # event 是一个事件对象
    print(event["event"], event["data"])
```

---

## 小结

流式输出的价值：
- ✅ **用户体验**：实时反馈，不用干等
- ✅ **调试友好**：看到每一步的执行过程
- ✅ **可交互性**：可以在流式输出中添加用户交互

LangGraph 的流式 API：
- `stream()`：节点级别的流式输出
- `stream_events()`：事件级别的细粒度流式输出
