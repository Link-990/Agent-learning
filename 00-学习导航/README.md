# 学习导航

这套资料不是按“把所有名词看一遍”设计的，而是按能力递进：先理解程序和模型怎样运行，再学 Agent 如何使用工具和状态，接着搭建 Runtime，最后进入框架、生产化和面试表达。

## 推荐主线

`text
基础与模型
  -> Agent 核心原理
  -> Agent Runtime
  -> RAG 与知识库
  -> 工具、协议与能力封装
  -> Agent 框架
  -> 企业级工程化
  -> 场景实战
  -> 系统设计
  -> 项目深挖与模拟面试
`

阅读主线时不要跳过 Runtime。它把文章里的 State、Event、Tool、Checkpoint 变成可以运行和排错的系统。

## 按目标选择

- 想理解 Agent：从 [基础与模型](../01-基础与模型/README.md) 开始，接着读 [Agent 核心原理](../02-Agent核心原理/README.md) 和 [Agent Runtime](../03-Agent-Runtime/README.md)。
- 想做 RAG：读完模型输入输出后进入 [RAG 与知识库](../04-RAG与知识库/README.md)，再看企业权限、同步和评测。
- 想做工具和自动化：先读 [工具、协议与能力封装](../05-工具、协议与能力封装/README.md)，再读企业工程化和场景实战。
- 想准备框架岗：完成 Agent Runtime 后进入 [Agent 框架](../06-Agent框架/README.md)，用统一 Runtime 术语比较不同框架。
- 想准备面试：完成一条主线后，用 [系统设计](../09-系统设计/README.md) 和 [项目深挖与模拟面试](../10-项目深挖与模拟面试/README.md) 输出答案。
- 想学习训练与对齐：把 [模型训练与对齐](../90-模型训练与对齐/README.md) 当作独立分支。

## 三种阅读模式

每篇文章都可以用三种方式学习：

1. **概念模式**：先读场景、机制、图和边界，形成因果链。
2. **实验模式**：运行代码，改变一个参数，故意制造一次失败，再观察状态和输出。
3. **面试模式**：隐藏文章，先用 30 秒讲结论，再用 2 分钟补架构、取舍和失败案例。

## 课程产出

学完一段内容后，应留下三种结果：一张自己画的流程图、一个可重复的最小实验、一段能说明边界的口头回答。不要把“读过文章”当作完成标准。
