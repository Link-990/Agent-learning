# 如何阅读与做实验

## 一篇文章的五次阅读

第一次只看标题、场景和总览图，写下系统要解决的一个矛盾。第二次读机制，画出输入、处理、状态和输出。第三次读代码，找出谁决定下一步和谁拥有副作用。第四次运行实验，记录正常结果。第五次注入一个失败，再解释系统为什么这样恢复或结束。

## Runtime 实验循环

`text
读问题场景
  -> 画状态和数据流
  -> 跑最小代码
  -> 故意制造失败
  -> 查看 Event 和 State
  -> 用四个问题复述
`

Runtime 的四个固定问题是：

1. 谁决定下一步执行什么？
2. 当前状态保存在哪里？
3. 任务失败后怎么办？
4. 外部能力经过什么边界被调用？

## 如何判断真的学会

你应该能在不看文章的情况下说明一个对象的责任、输入和失败边界；能把实验改成另一个场景；能解释一次失败是参数错误、权限拒绝、临时故障还是状态丢失；能说出为什么不能把所有控制权交给模型。

## 实验安全边界

本仓库的 Runtime 实验使用标准库、固定 mock 和临时文件，不需要真实密钥，不访问生产系统，不执行任意 shell。浏览器或未来的教学站点应保持同样边界，并把“模拟”与“真实运行”明确区分。
