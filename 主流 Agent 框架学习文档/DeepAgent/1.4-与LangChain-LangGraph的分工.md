# 1.4 与 LangChain / LangGraph 的分工

---

## 三者的定位

| 框架 | 定位 | 核心 API |
|------|------|---------|
| **LangGraph** | 低层工作流编排 | `StateGraph`、`@entrypoint` |
| **LangChain** | 中层 Agent 开发 | `create_agent()`、Middleware |
| **Deep Agents** | 上层复杂任务 | `create_deep_agent()`、subagents |

---

## 构建关系

```
Deep Agents
    ↓ 构建在
LangChain + LangGraph
    ↓ 构建在
LLM Provider
```

- `create_deep_agent()` 底层使用 LangGraph 的图结构
- `create_deep_agent()` 底层使用 LangChain 的工具系统和 Middleware

---

## 选择指南

| 需求 | 推荐框架 |
|------|---------|
| 简单的工具调用 Agent | LangChain `create_agent()` |
| 需要精确控制工作流 | LangGraph `StateGraph` |
| 需要文件读写 + 规划 + 子 Agent | Deep Agents |
| 需要持久化 + 暂停/恢复 | LangGraph |
| 需要 Middleware 定制 | LangChain 或 Deep Agents |

---

## Kami Code 的选择

Kami Code 选择了 Deep Agents，因为：
- 需要读写代码文件
- 需要几十个工具
- 需要长时间运行
- 需要工具延迟加载（Middleware）
