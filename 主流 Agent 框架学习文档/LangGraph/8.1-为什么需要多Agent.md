# 8.1 为什么需要多 Agent？

在实际应用中，让一个 Agent 做所有事情往往不是最优解。这一节我们用具体的例子来理解多 Agent 的必要性。

---

## 单 Agent 的问题

### 示例：一个"全能"Agent

```python
system_prompt = """
你是一个全能助手，你需要：
1. 搜索互联网获取信息
2. 分析数据和趋势
3. 撰写专业的研究报告
4. 审核报告的质量和准确性
5. 生成图表和可视化
6. 翻译成多种语言
7. 处理用户反馈
8. ...
"""
```

**问题**：
- ❌ Prompt 太长，LLM 容易"迷失"
- ❌ 每个任务都"略懂"，但不精
- ❌ 修改一个功能可能影响其他功能
- ❌ 难以测试和调试

---

## 多 Agent 的解决方案

### 拆分职责

```python
# 研究员 Agent
researcher_prompt = "你是一个研究专家，专注搜索和分析信息。"

# 写手 Agent
writer_prompt = "你是一个写作专家，专注生成高质量的内容。"

# 审核员 Agent
reviewer_prompt = "你是一个审核专家，专注检查内容的准确性和质量。"
```

**优势**：
- ✅ 每个 Agent 的 Prompt 简洁、专注
- ✅ 可以为每个 Agent 选择不同的模型（比如写手用 GPT-4，研究员用便宜的模型）
- ✅ 模块化，易于维护和扩展
- ✅ 可以并行执行

---

## 多 Agent 的应用场景

### 场景 1：内容生产流水线

```
研究员 → 写手 → 审核员 → 发布
```

- **研究员**：搜索资料，收集数据
- **写手**：基于资料撰写文章
- **审核员**：检查事实准确性、语法、风格
- **发布**：格式化并发布

### 场景 2：客服系统

```
路由 Agent → 技术支持 Agent
            → 账单 Agent
            → 投诉 Agent
```

- **路由 Agent**：判断用户问题的类型
- **技术支持 Agent**：处理技术问题
- **账单 Agent**：处理账单问题
- **投诉 Agent**：处理投诉

### 场景 3：代码审查

```
编码 Agent → 测试 Agent → 审查 Agent → 合并
```

- **编码 Agent**：编写代码
- **测试 Agent**：编写和运行测试
- **审查 Agent**：代码审查，检查质量

---

## 多 Agent vs 单 Agent 的选择

| 场景 | 单 Agent | 多 Agent |
|------|---------|---------|
| 简单任务（问答、翻译） | ✅ | ❌ 过度设计 |
| 中等复杂度（搜索+回答） | ✅ | ⚠️ 可以但没必要 |
| 高复杂度（研究+写作+审核） | ❌ 效果差 | ✅ 推荐 |
| 需要并行处理 | ❌ 串行执行 | ✅ 可以并行 |
| 需要专业分工 | ❌ 不够专业 | ✅ 各司其职 |

**经验法则**：
- 如果单 Agent 的 Prompt 超过 1000 字，考虑拆分
- 如果需要 3 种以上不同类型的工具，考虑拆分
- 如果执行时间超过 30 秒，考虑并行化

---

## 小结

多 Agent 的必要性：
- **职责分离**：每个 Agent 专注一件事
- **模块化解耦**：易于维护和扩展
- **并行执行**：提高效率
- **专业分工**：每个 Agent 可以做到最好

适用场景：
- 复杂的多步骤任务
- 需要不同专业能力的任务
- 需要并行处理的任务
