# 5.1 为什么需要持久化？

我们先从一个问题开始：**为什么 Agent 需要记忆？**

---

## 没有持久化的 Agent

### 示例：一个简单的对话 Agent

```python
from langgraph.graph import StateGraph, MessagesState, START, END
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o-mini")

def chat(state: MessagesState):
    response = llm.invoke(state["messages"])
    return {"messages": [response]}

graph = StateGraph(MessagesState)
graph.add_node("chat", chat)
graph.add_edge(START, "chat")
graph.add_edge("chat", END)

app = graph.compile()
```

### 测试

```python
# 第一轮对话
result = app.invoke({"messages": [{"role": "user", "content": "我叫 Alice"}]})
print(result["messages"][-1].content)
# 输出：你好 Alice！很高兴认识你。

# 第二轮对话
result = app.invoke({"messages": [{"role": "user", "content": "我叫什么名字？"}]})
print(result["messages"][-1].content)
# 输出：抱歉，我不知道你的名字。
```

**问题**：Agent **忘记了**第一轮对话！

因为每次调用 `app.invoke()` 都是**全新的执行**，之前的消息列表丢失了。

---

## 手动传递历史消息

### 修改代码

```python
# 手动维护消息列表
messages = []

# 第一轮
messages.append({"role": "user", "content": "我叫 Alice"})
result = app.invoke({"messages": messages})
messages.extend(result["messages"])

# 第二轮
messages.append({"role": "user", "content": "我叫什么名字？"})
result = app.invoke({"messages": messages})
print(result["messages"][-1].content)
# 输出：你叫 Alice。
```

**这样可以工作**，但是有几个问题：

1. **繁琐**：每次都要手动管理消息列表
2. **易错**：忘记 extend 就会丢失历史
3. **无法暂停/恢复**：如果程序崩溃，状态丢失
4. **无法回溯**：不能回到之前的某个状态

---

## 使用 Checkpointer

### 修改代码

```python
from langgraph.checkpoint.memory import MemorySaver

# 添加 checkpointer
checkpointer = MemorySaver()
app = graph.compile(checkpointer=checkpointer)

# 第一轮对话
result = app.invoke(
    {"messages": [{"role": "user", "content": "我叫 Alice"}]},
    config={"configurable": {"thread_id": "thread_1"}}
)

# 第二轮对话（同一个 thread_id）
result = app.invoke(
    {"messages": [{"role": "user", "content": "我叫什么名字？"}]},
    config={"configurable": {"thread_id": "thread_1"}}
)
print(result["messages"][-1].content)
# 输出：你叫 Alice。
```

**Checkpointer 自动保存了对话历史**——你不需要手动管理消息列表！

## Checkpointer 解决的问题

### 1. 多轮对话

```python
# 对话 1
app.invoke({"messages": [{"role": "user", "content": "我喜欢吃苹果"}]}, 
           config={"configurable": {"thread_id": "1"}})

# 对话 2
app.invoke({"messages": [{"role": "user", "content": "我喜欢什么？"}]}, 
           config={"configurable": {"thread_id": "1"}})
# 输出：你喜欢吃苹果。
```

### 2. 多个用户，独立对话

```python
# 用户 A 的对话
app.invoke({"messages": [{"role": "user", "content": "我叫 Alice"}]}, 
           config={"configurable": {"thread_id": "user_A"}})

# 用户 B 的对话
app.invoke({"messages": [{"role": "user", "content": "我叫 Bob"}]}, 
           config={"configurable": {"thread_id": "user_B"}})

# 用户 A 再次提问
result = app.invoke({"messages": [{"role": "user", "content": "我叫什么？"}]}, 
                    config={"configurable": {"thread_id": "user_A"}})
print(result["messages"][-1].content)
# 输出：你叫 Alice。（不会和 Bob 混淆）
```

### 3. 暂停/恢复

```python
from langgraph.func import entrypoint, interrupt
from langgraph.checkpoint.memory import MemorySaver

@entrypoint(checkpointer=MemorySaver())
def workflow(topic: str):
    plan = f"计划：{topic}"
    
    # 暂停，等待人工审批
    approved = interrupt({"plan": plan})
    
    if approved:
        return f"执行：{plan}"
    else:
        return "计划被拒绝"

# 第一次调用：会在 interrupt 处暂停
try:
    workflow("建设大楼", config={"configurable": {"thread_id": "1"}})
except:
    print("工作流已暂停")

# 人工审批后，恢复执行
from langgraph.types import Command
result = workflow.invoke(Command(resume=True), 
                        config={"configurable": {"thread_id": "1"}})
print(result)
# 输出：执行：计划：建设大楼
```

### 4. 时光倒流（回溯到历史状态）

```python
# 获取某个 thread 的所有历史状态
states = list(app.get_state_history(config={"configurable": {"thread_id": "1"}}))

# 回溯到第 3 个状态
old_state = states[2]
result = app.invoke(None, config=old_state.config)
```

## Store 解决的问题

Checkpointer 解决了"对话历史"的问题，但还有一些需求它解决不了：

### 问题 1：跨对话的记忆

```python
# 对话 1（thread_id = "1"）
app.invoke({"messages": [{"role": "user", "content": "我住在北京"}]}, 
           config={"configurable": {"thread_id": "1"}})

# 对话 2（thread_id = "2"，新对话）
result = app.invoke({"messages": [{"role": "user", "content": "我住在哪里？"}]}, 
                    config={"configurable": {"thread_id": "2"}})
# 输出：我不知道你住在哪里。
```

**Checkpointer 无法解决**——因为不同的 `thread_id` 是完全独立的。

**Store 可以解决**——Store 是跨 thread 共享的：

```python
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()

# 保存用户信息到 Store
store.put(("user", "user_123"), "location", {"city": "北京"})

# 在任何 thread 里都能读取
@entrypoint(store=store)
def workflow(user_id: str, store):
    items = store.search(("user", user_id))
    if items:
        city = items[0].value.get("city")
        return f"你住在 {city}"
    return "不知道你住在哪里"

result = workflow("user_123")
print(result)  # 输出：你住在北京
```

### 问题 2：知识库

Checkpointer 保存的是"对话历史"，不适合存储"知识"。

Store 更适合：

```python
# 保存 FAQ
store.put(("faq",), "how_to_refund", {"answer": "请联系客服申请退款"})
store.put(("faq",), "shipping_time", {"answer": "一般 3-5 个工作日"})

# 查询
items = store.search(("faq",))
for item in items:
    print(item.key, item.value)
```

## 小结

### 为什么需要持久化？

| 需求 | 手动管理 | Checkpointer | Store |
|------|---------|--------------|-------|
| 多轮对话 | ❌ 繁琐易错 | ✅ 自动保存 | ❌ 不适合 |
| 多用户独立对话 | ❌ 复杂 | ✅ 用 thread_id 隔离 | ❌ 不适合 |
| 暂停/恢复 | ❌ 无法实现 | ✅ 支持 interrupt | ❌ 不适合 |
| 时光倒流 | ❌ 无法实现 | ✅ 历史状态回溯 | ❌ 不适合 |
| 跨对话记忆 | ❌ 复杂 | ❌ 无法跨 thread | ✅ 跨 thread 共享 |
| 知识库 | ❌ 不合适 | ❌ 不合适 | ✅ 适合 |

### Checkpointer vs Store

- **Checkpointer**：保存"执行历史"（对话历史、中间状态）
- **Store**：保存"长期知识"（用户信息、知识库）

两者可以同时使用，配合使用效果最好。
