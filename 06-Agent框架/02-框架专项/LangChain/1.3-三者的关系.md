# 1.3 LangChain vs LangGraph vs Deep Agents

在 LangChain 生态中，有三个核心框架：**LangChain**、**LangGraph**、**Deep Agents**。搞清楚它们之间的关系，是学习的第一步。

---

## 一句话区分

| 框架 | 一句话 |
|------|-------|
| **LangChain** | 最小化的 Agent 开发框架，`create_agent()` 搞定一切 |
| **LangGraph** | 低层工作流编排框架，用"图"来控制 Agent 的执行流程 |
| **Deep Agents** | 上层 Agent 框架，内置规划、子 Agent、文件系统等高级功能 |

---

## 三者的关系

```
Deep Agents（最上层）
    ↓ 构建在
LangChain（中间层）
    ↓ 构建在
LangGraph（底层）
```

等等，这个关系图不完全准确。更准确的关系是：

```
Deep Agents
    ↓ 使用
LangChain + LangGraph
    ↓
LLM Provider (OpenAI, Anthropic, ...)
```

实际上：
- **LangChain** 的 `create_agent()` 底层使用 **LangGraph** 来实现 Agent 循环
- **Deep Agents** 的 `create_deep_agent()` 底层同时使用 **LangChain** 和 **LangGraph**

---

## 功能对比

| 特性 | LangChain | LangGraph | Deep Agents |
|------|-----------|-----------|-------------|
| Agent 创建 | `create_agent()` | `StateGraph` + 手动编排 | `create_deep_agent()` |
| 工具调用 | ✅ | ✅ | ✅ |
| 工作流编排 | ❌ 不支持 | ✅ 核心能力 | ✅ 内置 |
| 持久化 | ❌ | ✅ Checkpointer + Store | ✅ 内置 |
| 子 Agent | ❌ | 需要手动编排 | ✅ 内置 |
| 文件系统 | ❌ | ❌ | ✅ 虚拟文件系统 |
| 规划工具 | ❌ | ❌ | ✅ write_todos |
| Middleware | ✅ 核心能力 | ❌ | ✅ 继承自 LangChain |
| 学习曲线 | 低 | 中高 | 中 |

---

## 什么时候用哪个？

### 用 LangChain

- ✅ 简单的 Agent（调用 LLM + 工具）
- ✅ 需要 Middleware 定制行为
- ✅ 不需要复杂的工作流
- ✅ 快速原型开发

```python
from langchain.agents import create_agent

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[search, calculator],
    middleware=[SummarizationMiddleware()]
)
```

### 用 LangGraph

- ✅ 需要精确控制工作流
- ✅ 需要持久化（对话历史、暂停/恢复）
- ✅ 需要复杂的条件路由、循环
- ✅ 需要人工介入（interrupt）

```python
from langgraph.graph import StateGraph, START, END

graph = StateGraph(State)
graph.add_node("llm", call_llm)
graph.add_node("tools", call_tools)
graph.add_edge(START, "llm")
graph.add_conditional_edges("llm", route, {"tools": "tools", "end": END})
graph.add_edge("tools", "llm")
app = graph.compile(checkpointer=MemorySaver())
```

### 用 Deep Agents

- ✅ 复杂的多步骤任务
- ✅ 需要规划（write_todos）
- ✅ 需要子 Agent 委派
- ✅ 需要文件系统访问
- ✅ 长时间运行的任务

```python
from deepagents import create_deep_agent

agent = create_deep_agent(
    model="openai:gpt-5.5",
    subagents=[
        {"name": "researcher", "description": "搜索资料"},
        {"name": "writer", "description": "写文章"},
    ]
)
```

---

## Kami Code 的选择

Kami Code（我们的实战项目）选择了 **Deep Agents** 作为核心框架：

```
Kami Code
    ↓ 使用
deepagents（核心框架）
    ↓ 使用
LangChain（工具协议 + Middleware）
    ↓ 使用
LangGraph（底层编排引擎）
```

为什么选 Deep Agents？
- 需要文件系统访问（读写代码文件）
- 需要工具系统（几十个工具）
- 需要 Middleware（延迟加载工具过滤）
- 需要长时间运行（编程任务复杂）

同时，Kami Code 也使用了 LangChain 的：
- `StructuredTool`：工具协议对齐
- `AgentMiddleware`：延迟加载过滤
- `usage_metadata`：Token 用量统计

---

## 学习顺序建议

1. **先学 LangGraph**（已完成✅）：理解底层编排
2. **再学 LangChain**（正在学）：理解上层 API
3. **最后学 Deep Agents**：理解全家桶

---

## 小结

| 框架 | 定位 | 适合场景 |
|------|------|---------|
| LangChain | 最小化 Agent 框架 | 简单 Agent、快速原型 |
| LangGraph | 低层工作流编排 | 复杂工作流、持久化 |
| Deep Agents | 上层全家桶 | 复杂多步骤任务 |

三者的关系：
- LangChain 的 `create_agent()` 底层用 LangGraph
- Deep Agents 同时用 LangChain 和 LangGraph
- 三个框架可以混合使用
