# 第四章：Functional API——函数式构建方式

前面三章我们学的是 StateGraph API——定义 State、添加节点、添加边。这是 LangGraph 的"经典方式"。

从 LangGraph v1.0 开始，引入了一种全新的 API：**Functional API**。它让你用"写普通 Python 函数"的方式构建 Agent，不需要显式定义图、节点、边。

这一章我们学习这种更简洁、更直观的构建方式。

## 为什么要学 Functional API？

### StateGraph API 的问题

回想一下，用 StateGraph 写一个简单的工作流：

```python
graph = StateGraph(State)
graph.add_node("step1", step1_func)
graph.add_node("step2", step2_func)
graph.add_edge(START, "step1")
graph.add_edge("step1", "step2")
graph.add_edge("step2", END)
app = graph.compile()
```

这样写虽然清晰，但有点"啰嗦"——你要：
1. 定义 State
2. 创建 graph
3. 添加节点
4. 添加边
5. 编译

**Functional API 的理念**：如果工作流的逻辑本身就是"普通 Python 控制流"（if、for、while），为什么还要显式定义图？

### Functional API 的方式

用 Functional API，同样的逻辑：

```python
@entrypoint
def workflow(input: str):
    result1 = step1(input)
    result2 = step2(result1)
    return result2
```

就这么简单！用普通的函数调用、if 判断、循环，自然地表达工作流。

---

## 两种 API 的适用场景

| 场景 | 推荐 API |
|------|---------|
| 工作流逻辑简单，线性或少量分支 | Functional API |
| 需要复杂的循环、动态路由 | StateGraph API |
| 需要可视化图结构 | StateGraph API |
| 快速原型开发 | Functional API |
| 需要精细控制每个节点 | StateGraph API |
| 团队更熟悉函数式编程 | Functional API |

简单说：**Functional API 更简洁，StateGraph API 更灵活**。

---

## 学习方法建议

Functional API 是 StateGraph 的"语法糖"——底层还是编译成图。所以：
- 如果你已经掌握了 StateGraph（前三章），理解 Functional API 会很快
- 如果你直接学 Functional API，可能会对某些行为（如 interrupt）感到困惑

**建议顺序**：先学 StateGraph（已完成✅），再学 Functional API（本章）。

**预计学习时间：1-1.5 小时**
