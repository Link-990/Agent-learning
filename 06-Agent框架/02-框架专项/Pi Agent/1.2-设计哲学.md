# 1.2 Pi 的设计哲学

Pi 的设计哲学可以总结为：**让工具适应你，而不是你适应工具。**

---

## 极简核心

Pi **刻意不内置**很多功能：
- 不内置 MCP 客户端
- 不内置子 Agent
- 不内置计划模式
- 不内置权限弹窗

为什么？因为每个人的工作流不同。内置了反而会限制你。

Pi 的做法是：提供**基础原语**（primitives），让你通过 Extension 自己构建。

---

## 类比

| 框架 | 类比 |
|------|------|
| Claude Code | 像一个成品手机——开箱即用 |
| Pi | 像一个 Linux 发行版——需要自己配置，但完全可控 |

---

## 自我修改

Pi 最独特的特性之一：**它可以在运行时修改自己的代码**。

```
用户: 添加一个 /deploy 命令
Pi: 好的，我来写一个 Extension...
    [Pi 修改了自己的 Extension 文件]
    /reload 完成，新命令已生效
```

这在其他 Agent 中几乎看不到。

---

## 包管理

Pi 支持把 Extension、Skills、主题打包成 **Pi packages**，通过 npm 或 git 分发。

```bash
# 安装社区 Extension
npm install pi-subagents
```
