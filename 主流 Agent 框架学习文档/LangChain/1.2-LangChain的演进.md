# 1.2 LangChain 的演进：从 v0.x 到 v1.0+ 的巨变

如果你在网上搜 LangChain 教程，大概率会看到一堆过时的内容。这一节告诉你 LangChain 经历了什么变化，避免你踩坑。

---

## v0.x 时代（2023-2024 上半年）

### 当时的 LangChain

```python
# 旧的 Chain 模式
from langchain.chains import LLMChain
from langchain.prompts import PromptTemplate
from langchain.llms import OpenAI

prompt = PromptTemplate(template="你好，{name}", input_variables=["name"])
llm = OpenAI()
chain = LLMChain(llm=llm, prompt=prompt)
result = chain.run(name="Alice")
```

### 特点

- **Chain（链）**：把组件串成一条链，线性执行
- **AgentExecutor**：一个黑盒，自动处理 Agent 循环
- **大量的类**：各种 Chain、Memory、Retriever 类
- **复杂**：概念多，学习曲线陡

### 问题

1. **Chain 太僵硬**：只能线性执行，不能循环、分支
2. **AgentExecutor 是黑盒**：不透明，不好调试
3. **类太多**：几十个类，不知道用哪个
4. **不灵活**：很难定制 Agent 的行为

---

## LCEL 时代（2024 上半年）

### LangChain Expression Language

为了解决 Chain 的僵硬问题，LangChain 推出了 LCEL——用管道符 `|` 连接组件：

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_template("翻译：{text}")
model = ChatOpenAI()
parser = StrOutputParser()

chain = prompt | model | parser
result = chain.invoke({"text": "Hello"})
```

### 特点

- **管道符**：`|` 连接组件，更灵活
- **Runnable 接口**：所有组件都实现 `invoke`、`stream`、`batch`
- **可组合**：可以任意组合组件

### 问题

- LCEL 解决了"链"的灵活性，但还是不能处理 Agent 的循环逻辑
- 概念还是太多

---

## v1.0 时代（2025 年 10 月至今）

### "推倒重来"

2025 年 10 月 20 日，LangChain 发布了 **v1.0**——这是一次"推倒重来"式的重构：

- ❌ 移除了**所有旧的 Chain 类**（LLMChain、SequentialChain 等）
- ❌ 移除了**AgentExecutor**
- ❌ 移除了**旧的记忆系统**
- ✅ 引入了 **`create_agent()`**——统一的 Agent 入口
- ✅ 引入了 **Middleware 系统**——可插拔的中间件
- ✅ 引入了 **Tool extras**——Provider-specific 功能

### 现在的 LangChain

```python
from langchain.agents import create_agent

# 就这么简单
agent = create_agent(
    model="openai:gpt-5.5",
    tools=[...],
    middleware=[...],
    system_prompt="..."
)

result = agent.invoke({"messages": [...]})
```

---

## 版本对照表

| 特性 | v0.x（旧） | v1.0+（新） |
|------|-----------|-----------|
| Agent 创建 | `AgentExecutor` | `create_agent()` |
| 链 | `LLMChain`、`SequentialChain` | 已移除，用 LangGraph |
| 定制行为 | 继承类重写方法 | Middleware 系统 |
| 模型调用 | `OpenAI()`、`ChatOpenAI()` | `create_agent(model="provider:model")` |
| 工具定义 | `@tool` 或 `StructuredTool` | `@tool`（简化了） |
| 消息系统 | `AIMessage`、`HumanMessage` | 基本没变 |

---

## 如何识别过时的教程？

### ❌ 过时的标志

- 使用 `from langchain.chains import ...`
- 使用 `AgentExecutor`
- 使用 `LLMChain`
- 使用 `from langchain.llms import OpenAI`
- 版本低于 v0.3

### ✅ 最新的标志

- 使用 `create_agent()`
- 使用 `from langchain.agents import create_agent`
- 使用 Middleware
- 使用 `model="provider:model"` 字符串格式
- 版本 v1.0+

## 小结

LangChain 的演进：
1. **v0.x**：Chain + AgentExecutor，复杂但功能全
2. **LCEL**：管道符，更灵活，但还是不能处理 Agent
3. **v1.0+**：`create_agent()` + Middleware，极简但强大

**学习建议**：
- 直接学 v1.0+ 的 API
- 忽略所有使用 `AgentExecutor`、`LLMChain` 的教程
- 如果看到旧的教程，先确认版本号
