# 2.4 一个最简图：Hello LangGraph

理论讲了这么多，现在我们真正动手，从零开始写一个完整的 LangGraph 应用。

这一节的目标：**写一个能跑通的最简 Agent**，让你把 State、Node、Edge 三个概念串起来。

---

## 我们要做什么？

一个最简单的"问答 Agent"：
1. 用户输入问题
2. 调用 LLM 回答
3. 返回结果

流程图：

```
START → call_llm → END
```

就这么简单。

---

## 完整代码

创建一个文件 `hello_langgraph.py`：

```python
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langgraph.graph import StateGraph, MessagesState, START, END

# 加载环境变量（需要配置 OPENAI_API_KEY）
load_dotenv()

# 初始化 LLM
llm = ChatOpenAI(model="gpt-4o-mini")

# 定义节点：调用 LLM
def call_llm(state: MessagesState):
    """接收消息，调用 LLM，返回回复"""
    messages = state["messages"]
    response = llm.invoke(messages)
    return {"messages": [response]}

# 构建图
graph = StateGraph(MessagesState)

# 添加节点
graph.add_node("llm", call_llm)

# 添加边
graph.add_edge(START, "llm")  # 从开始到 LLM
graph.add_edge("llm", END)    # 从 LLM 到结束

# 编译图
app = graph.compile()

# 运行
if __name__ == "__main__":
    result = app.invoke({
        "messages": [{"role": "user", "content": "你好"}]
    })
    
    # 打印最后一条消息（LLM 的回复）
    print(result["messages"][-1].content)
```

## 逐行解读

### 1. 导入必要的库

```python
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langgraph.graph import StateGraph, MessagesState, START, END
```

- `load_dotenv`：加载 `.env` 文件里的 API Key
- `ChatOpenAI`：OpenAI 的 LLM 封装
- `StateGraph`：LangGraph 的图构建器
- `MessagesState`：内置的"消息列表"状态
- `START`、`END`：起点和终点

### 2. 加载环境变量和初始化 LLM

```python
load_dotenv()
llm = ChatOpenAI(model="gpt-4o-mini")
```

确保你的 `.env` 文件里有：

```
OPENAI_API_KEY=你的API_KEY
```

### 3. 定义节点

```python
def call_llm(state: MessagesState):
    messages = state["messages"]
    response = llm.invoke(messages)
    return {"messages": [response]}
```

这个节点做了什么？
- 从 State 里读取 `messages`（对话历史）
- 调用 LLM，传入对话历史
- 返回 LLM 的回复，**追加**到 messages 列表

### 4. 构建图

```python
graph = StateGraph(MessagesState)
```

创建一个图，使用 `MessagesState` 作为 State 类型。

### 5. 添加节点

```python
graph.add_node("llm", call_llm)
```

给图添加一个节点，名字叫 `"llm"`，对应的函数是 `call_llm`。

### 6. 添加边

```python
graph.add_edge(START, "llm")
graph.add_edge("llm", END)
```

- 从 `START` 到 `"llm"`：执行开始时，先执行 llm 节点
- 从 `"llm"` 到 `END`：llm 节点执行完，就结束

### 7. 编译图

```python
app = graph.compile()
```

把图"编译"成可执行的对象。

### 8. 运行

```python
result = app.invoke({
    "messages": [{"role": "user", "content": "你好"}]
})
```

调用 `invoke`，传入初始 State。

返回值 `result` 是**最终的 State**，包含完整的对话历史。

### 9. 打印结果

```python
print(result["messages"][-1].content)
```

取最后一条消息（LLM 的回复），打印内容。

```bash
python hello_langgraph.py
```

输出：

```
你好！有什么我可以帮助你的吗？
```

恭喜，你的第一个 LangGraph Agent 跑起来了！

## 修改一下：多轮对话

现在这个 Agent 只能问一次。如果想多轮对话呢？

只需要在 `result["messages"]` 里追加用户的新消息，再调用一次：

```python
# 第一轮
result = app.invoke({
    "messages": [{"role": "user", "content": "你好"}]
})
print("AI:", result["messages"][-1].content)

# 第二轮：继续对话
result = app.invoke({
    "messages": result["messages"] + [
        {"role": "user", "content": "你叫什么名字？"}
    ]
})
print("AI:", result["messages"][-1].content)
```

输出：

```
AI: 你好！有什么我可以帮助你的吗？
AI: 我是 Claude，一个 AI 助手。很高兴认识你！
```

看到了吗？第二轮对话时，我们把第一轮的 `messages` 传了进去，所以 LLM 能记住之前的对话。

## 调试：查看每一步的执行

如果想看每一步的状态变化，用 `stream()`：

```python
for event in app.stream({"messages": [{"role": "user", "content": "你好"}]}):
    print(event)
```

输出：

```
{'llm': {'messages': [AIMessage(content='你好！有什么我可以帮助你的吗？')]}}
```

`stream()` 会返回一个生成器，每执行完一个节点，就输出一次。

## 小结

这个最简 Agent 虽然简单，但包含了 LangGraph 的所有核心要素：

1. **State**：`MessagesState`，存储对话历史
2. **Node**：`call_llm`，调用 LLM 的函数
3. **Edge**：`START → llm → END`，定义执行顺序
4. **编译**：`graph.compile()`，生成可执行对象
5. **运行**：`app.invoke(initial_state)`，传入初始状态

代码结构清晰：
- 定义节点 → 构建图 → 添加节点 → 添加边 → 编译 → 运行

这就是 LangGraph 的标准写法，后面所有复杂的 Agent 都是基于这个模式。
