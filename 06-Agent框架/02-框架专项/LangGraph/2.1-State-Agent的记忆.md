# 2.1 State——Agent 的"记忆"

在 LangGraph 中，**State（状态）** 是最核心的概念。可以把它想象成一个"共享的黑板"——所有节点都可以在这块黑板上读取信息、写入信息。

---

## 为什么需要 State？

回想一下，一个 Agent 的执行过程通常是这样的：

```
节点 A：用户输入 → LLM 判断需要查天气
节点 B：调用天气 API，拿到 "晴天，25°C"
节点 C：把天气信息喂给 LLM，生成回复
```

这三个节点之间需要传递信息：
- 节点 B 需要知道"LLM 想查哪个城市的天气"
- 节点 C 需要知道"天气 API 返回了什么"

传统的做法是用全局变量或者参数传递，但这样很乱。LangGraph 的做法是：**所有节点共享一个 State 对象**。

---

## State 的本质：一个 Python 字典

State 其实就是一个 Python 字典（dict）：

```python
state = {
    "messages": [...],
    "city": "北京",
    "weather": "晴天，25°C"
}
```

每个节点可以：
- **读取** State：`city = state["city"]`
- **更新** State：`return {"weather": "晴天，25°C"}`

LangGraph 会自动把返回值合并到 State 里。

---

## 定义 State 的两种方式

### 方式 1：用 Python 的 TypedDict（推荐）

```python
from typing import TypedDict

class AgentState(TypedDict):
    messages: list
    city: str
    weather: str
```

这样定义的好处：
- **类型明确**：一眼看出 State 里有哪些字段，每个字段是什么类型
- **IDE 支持好**：VS Code 会给你自动补全和类型检查

### 方式 2：直接用 dict（不推荐，除非做快速实验）

```python
state = {"messages": [], "city": "", "weather": ""}
```

这种方式虽然简单，但没有类型检查，容易出错。

---

## State 的更新机制：合并，而不是替换

这是一个很重要的细节。

假设当前 State 是：

```python
{"messages": ["你好"], "city": "北京"}
```

节点返回：

```python
{"weather": "晴天"}
```

LangGraph 会**合并**这两个字典，而不是替换：

```python
{"messages": ["你好"], "city": "北京", "weather": "晴天"}
```

也就是说，节点只需要返回"需要更新的字段"，其他字段会保持原样。

---

## 特殊字段：messages（消息列表）

如果你在做对话 Agent，State 里通常会有一个 `messages` 字段，用来存储对话历史。

LangGraph 提供了一个内置的 State 类型：**MessagesState**

```python
from langgraph.graph import MessagesState

# MessagesState 相当于：
class MessagesState(TypedDict):
    messages: Annotated[list, add_messages]
```

`add_messages` 是一个特殊的"reducer"，作用是：
- 如果节点返回 `{"messages": [新消息]}`，新消息会**追加**到列表末尾
- 而不是替换整个列表

举个例子：

```python
# 当前 State
state = {"messages": [{"role": "user", "content": "你好"}]}

# 节点返回
return {"messages": [{"role": "ai", "content": "你好！"}]}

# 合并后的 State
state = {
    "messages": [
        {"role": "user", "content": "你好"},
        {"role": "ai", "content": "你好！"}
    ]
}
```

看到了吗？新消息被**追加**了，而不是替换掉旧消息。

---

## 自定义 State 的更新逻辑：Annotated + Reducer

有时候你想自定义"合并逻辑"。比如：
- 字段 A 应该追加（像 `messages`）
- 字段 B 应该取最大值
- 字段 C 应该替换（默认行为）

可以用 `Annotated` + `reducer` 函数：

```python
from typing import TypedDict, Annotated
from operator import add

def take_max(existing, new):
    """取最大值"""
    return max(existing, new)

class MyState(TypedDict):
    messages: Annotated[list, add]  # 追加
    score: Annotated[int, take_max]  # 取最大值
    city: str  # 默认：替换
```

这样：
- `messages` 会追加
- `score` 会取最大值（如果新值更大）
- `city` 会直接替换

---

## 实战示例：带 State 的节点

```python
from typing import TypedDict

class AgentState(TypedDict):
    input: str
    result: str

def process_input(state: AgentState):
    """处理用户输入"""
    user_input = state["input"]
    processed = user_input.upper()  # 转大写
    return {"result": processed}

# 测试一下
initial_state = {"input": "hello", "result": ""}
updated_state = process_input(initial_state)
print(updated_state)  # {"result": "HELLO"}
```

看到了吗？
1. 节点函数接收 `state` 参数
2. 从 `state` 里读取需要的信息
3. 返回一个字典，只包含需要更新的字段
4. LangGraph 会自动合并到 State 里

---

## State 的生命周期

```
1. 创建初始 State
   ↓
2. 传给第一个节点
   ↓
3. 节点返回更新
   ↓
4. LangGraph 合并 State
   ↓
5. 传给下一个节点
   ↓
... (重复 3-5)
   ↓
6. 最后返回最终 State
```

整个执行过程中，State 就像一个接力棒，在节点之间传递和更新。

---

## 小结

- **State 是什么**：一个所有节点共享的字典，用来在节点之间传递信息
- **如何定义**：用 `TypedDict`，明确字段和类型
- **如何更新**：节点返回字典，LangGraph 自动合并（不是替换）
- **特殊字段**：`messages` 用 `Annotated[list, add_messages]` 实现追加
- **自定义逻辑**：用 `Annotated` + `reducer` 函数

State 是 LangGraph 的"数据流"核心——掌握了它，你就掌握了节点之间如何通信。
