# 1.2 为什么需要 Deep Agents？

普通 Agent 在处理简单任务时很好用，但面对复杂任务时会力不从心。

---

## 普通 Agent 的局限

### 局限 1：没有文件系统

Agent 收集了大量信息，只能放在对话上下文中。信息量一大，上下文窗口就满了。

### 局限 2：没有规划能力

Agent 只会"一步接一步"执行，不会先制定计划再执行。对于复杂任务，容易遗漏步骤。

### 局限 3：不能委派

所有事情都自己干，不能把子任务分给"专家"去处理。

### 局限 4：上下文管理

对话一长，Token 消耗就很大。没有自动压缩机制。

---

## Deep Agents 的解决方案

| 局限 | Deep Agents 的解决 |
|------|-------------------|
| 没有文件系统 | 内置虚拟文件系统（StateBackend / FilesystemBackend） |
| 没有规划 | 内置 write_todos 规划工具 |
| 不能委派 | 内置子 Agent 委派系统（subagents + task 命令） |
| 上下文管理 | 自动压缩 + 输出卸载到磁盘 |

---

## 什么时候用 Deep Agents？

### 适合的场景

- ✅ 需要读写文件的任务（代码生成、文档编写）
- ✅ 需要多步骤规划的任务（研究报告、项目分析）
- ✅ 需要子任务委派的任务（多人协作、专业分工）
- ✅ 长时间运行的任务（需要持久化和恢复）
- ✅ 需要人工审批的任务（文件写入前审批）

### 不适合的场景

- ❌ 简单的问答（用 LangChain `create_agent()` 就够了）
- ❌ 简单的工具调用（不需要文件系统和规划）
- ❌ 实时对话（Deep Agents 更偏"批处理"）

---

## 小结

Deep Agents 解决的核心问题：
- 复杂任务需要规划
- 大量数据需要文件系统
- 专业分工需要子 Agent 委派
- 长对话需要上下文管理
