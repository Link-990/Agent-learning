# 6.4 interrupt_before / interrupt_after：在节点级别暂停

除了用 `interrupt()` 在代码里显式暂停，LangGraph 还支持**在节点级别暂停**——通过 `interrupt_before` 和 `interrupt_after` 参数。

这种方式更适合 StateGraph API，让你在不修改节点代码的情况下，添加暂停点。

---

## 基本用法

### 在 compile 时指定

```python
app = graph.compile(
    checkpointer=checkpointer,
    interrupt_before=["node_name"],  # 在这个节点之前暂停
    interrupt_after=["node_name"]    # 在这个节点之后暂停
)
```

---

## interrupt_before vs interrupt_after

### interrupt_before

在执行节点**之前**暂停。

```python
app = graph.compile(
    checkpointer=MemorySaver(),
    interrupt_before=["critical_node"]
)
```

执行流程：
1. 执行前面的节点
2. **暂停**，等待人类输入
3. 人类确认后，执行 `critical_node`

### interrupt_after

在执行节点**之后**暂停。

```python
app = graph.compile(
    checkpointer=MemorySaver(),
    interrupt_after=["critical_node"]
)
```

执行流程：
1. 执行 `critical_node`
2. **暂停**，等待人类输入
3. 人类确认后，继续执行后面的节点

## 完整示例

### 定义工作流

```python
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.checkpoint.memory import MemorySaver
from langgraph.types import Command
from langchain_openai import ChatOpenAI
from typing import TypedDict

llm = ChatOpenAI(model="gpt-4o-mini")

class State(TypedDict):
    messages: list
    plan: str
    approved: bool

def plan_node(state: State):
    """生成执行计划"""
    plan = "执行方案：分 3 个阶段实施"
    return {"plan": plan, "messages": [{"role": "assistant", "content": plan}]}

def execute_node(state: State):
    """执行计划"""
    return {"messages": [{"role": "assistant", "content": "计划已执行"}]}

# 构建图
graph = StateGraph(State)
graph.add_node("plan", plan_node)
graph.add_node("execute", execute_node)

graph.add_edge(START, "plan")
graph.add_edge("plan", "execute")
graph.add_edge("execute", END)

# 在 plan 节点之后暂停
checkpointer = MemorySaver()
app = graph.compile(
    checkpointer=checkpointer,
    interrupt_after=["plan"]  # plan 执行完后暂停
)
```

### 执行工作流

```python
thread_id = "interrupt_test_1"

# 第一次调用：会在 plan 节点后暂停
result = app.invoke(
    {"messages": [], "plan": "", "approved": False},
    config={"configurable": {"thread_id": thread_id}}
)

# 查看状态
state = app.get_state(config={"configurable": {"thread_id": thread_id}})
print(f"当前计划：{state.values['plan']}")
print(f"下一步：{state.next}")  # ('execute',)

# 人类审批：批准
result = app.invoke(
    Command(resume={"approved": True}),
    config={"configurable": {"thread_id": thread_id}}
)

print(f"最终结果：{result['messages'][-1]['content']}")
```

## interrupt_before 的示例

```python
app = graph.compile(
    checkpointer=checkpointer,
    interrupt_before=["execute"]  # execute 执行前暂停
)

# 第一次调用：会在 execute 之前暂停
result = app.invoke(
    {"messages": [], "plan": "", "approved": False},
    config={"configurable": {"thread_id": thread_id}}
)

# 查看状态
state = app.get_state(config={"configurable": {"thread_id": thread_id}})
print(f"计划已生成：{state.values['plan']}")
print(f"即将执行：{state.next}")  # ('execute',)

# 人类审批
result = app.invoke(
    Command(resume={"approved": True}),
    config={"configurable": {"thread_id": thread_id}}
)
```

---

## 暂停点的信息

暂停时，可以通过 `get_state()` 查看暂停点的信息：

```python
state = app.get_state(config={"configurable": {"thread_id": thread_id}})

# 查看当前状态值
print(f"State: {state.values}")

# 查看下一步要执行的节点
print(f"Next: {state.next}")

# 查看 interrupt 的 payload
if state.next:
    print(f"Interrupt at: {state.next[0]}")
```

---

## 多个暂停点

可以同时指定多个节点的暂停：

```python
app = graph.compile(
    checkpointer=MemorySaver(),
    interrupt_before=["node_a", "node_b"],
    interrupt_after=["node_c"]
)
```

## 动态修改暂停点

有时候你希望根据运行时条件，动态决定是否暂停。

### 方法：用 update_state 修改

```python
# 获取当前状态
state = app.get_state(config={"configurable": {"thread_id": thread_id}})

# 修改状态（比如添加一个字段）
app.update_state(
    config={"configurable": {"thread_id": thread_id}},
    values={"user_approved": True}
)

# 继续执行
result = app.invoke(
    Command(resume=None),
    config={"configurable": {"thread_id": thread_id}}
)
```

---

## interrupt_before/after vs interrupt()

### 对比

| 特性 | interrupt() | interrupt_before/after |
|------|-------------|------------------------|
| 暂停位置 | 代码里任意位置 | 节点之前或之后 |
| 灵活性 | 高 | 低（只能是节点级别） |
| 代码侵入 | 需要修改节点代码 | 不需要修改节点代码 |
| 适用 API | Functional API | StateGraph API |

### 选择建议

- **Functional API**：用 `interrupt()`
- **StateGraph API**：用 `interrupt_before` / `interrupt_after`

## 实战：一个带审批的 ReAct Agent

```python
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.checkpoint.memory import MemorySaver
from langgraph.types import Command
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool

llm = ChatOpenAI(model="gpt-4o-mini")

@tool
def send_email(to: str, subject: str, body: str) -> str:
    """发送邮件"""
    return f"已发送邮件给 {to}，主题：{subject}"

tools = [send_email]
llm_with_tools = llm.bind_tools(tools)

def call_llm(state: MessagesState):
    response = llm_with_tools.invoke(state["messages"])
    return {"messages": [response]}

def call_tools(state: MessagesState):
    last_message = state["messages"][-1]
    tool_calls = last_message.tool_calls
    
    results = []
    for tool_call in tool_calls:
        if tool_call["name"] == "send_email":
            result = send_email.invoke(tool_call["args"])
            results.append({
                "role": "tool",
                "content": result,
                "tool_call_id": tool_call["id"]
            })
    
    return {"messages": results}

def should_continue(state: MessagesState):
    last_message = state["messages"][-1]
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        return "tools"
    return "end"

# 构建图
graph = StateGraph(MessagesState)
graph.add_node("llm", call_llm)
graph.add_node("tools", call_tools)

graph.add_edge(START, "llm")
graph.add_conditional_edges("llm", should_continue, {
    "tools": "tools",
    "end": END
})
graph.add_edge("tools", "llm")

# 在 tools 节点之前暂停（等待人工审批）
checkpointer = MemorySaver()
app = graph.compile(
    checkpointer=checkpointer,
    interrupt_before=["tools"]  # 工具执行前暂停
)

# 测试
thread_id = "email_agent_1"

# 用户请求
result = app.invoke(
    {"messages": [{"role": "user", "content": "发邮件给 alice@example.com，主题：会议，内容：明天下午 3 点开会"}]},
    config={"configurable": {"thread_id": thread_id}}
)

# 查看状态：应该在 tools 之前暂停
state = app.get_state(config={"configurable": {"thread_id": thread_id}})
print(f"下一步：{state.next}")  # ('tools',)
print(f"即将调用工具：{state.values['messages'][-1].tool_calls}")

# 人工审批：批准
result = app.invoke(
    Command(resume=None),  # 不需要传入值，继续执行即可
    config={"configurable": {"thread_id": thread_id}}
)

print(f"最终结果：{result['messages'][-1].content}")
```

## 小结

`interrupt_before` / `interrupt_after` 的用法：

**指定暂停点**：
```python
app = graph.compile(
    checkpointer=checkpointer,
    interrupt_before=["node_a"],  # 在 node_a 之前暂停
    interrupt_after=["node_b"]    # 在 node_b 之后暂停
)
```

**恢复执行**：
```python
app.invoke(Command(resume=value), config={"configurable": {"thread_id": "..."}})
```

**适用场景**：
- 需要在特定节点暂停
- 不想修改节点代码
- StateGraph API

**与 interrupt() 的对比**：
- `interrupt()`：代码级别，更灵活
- `interrupt_before/after`：节点级别，更简单
