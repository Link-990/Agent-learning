# 4.1 什么是 Middleware？

Middleware（中间件）是一种**可插拔的 Agent 行为定制机制**。

---

## 类比理解

把 Agent 想象成一个工厂流水线：

```
原材料 → [加工] → [质检] → [包装] → 成品
```

Middleware 就是在流水线上**插入额外的工序**：

```
原材料 → [Logging] → [加工] → [审批] → [质检] → [摘要] → [包装] → 成品
```

你不需要改变原有的工序，只需要在合适的位置插入 Middleware。

---

## 代码层面

```python
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware

agent = create_agent(
    model="openai:gpt-4o-mini",
    tools=[...],
    middleware=[
        SummarizationMiddleware()  # 插入一个"摘要"中间件
    ]
)
```

Middleware 可以拦截 Agent 的：
- **模型调用前**：修改输入、过滤工具
- **模型调用后**：修改输出、记录日志
- **工具执行前**：审批、权限检查
- **工具执行后**：结果过滤、格式化

---

## 为什么需要 Middleware？

### 没有 Middleware

你想在每次 LLM 调用前记录日志，就得：
1. 继承 Agent 类
2. 重写 invoke 方法
3. 在调用前后加日志

**问题**：代码耦合、难以维护。

### 有 Middleware

```python
class LoggingMiddleware(AgentMiddleware):
    def wrap_model_call(self, request, handler):
        print("LLM 调用开始")
        response = handler(request)
        print("LLM 调用结束")
        return response

agent = create_agent(
    model="gpt-4o-mini",
    tools=[],
    middleware=[LoggingMiddleware()]
)
```

**优势**：解耦、可复用、可组合。

---

## Kami Code 中的 Middleware

Kami Code 用 `DeferredToolMiddleware` 实现了"延迟加载工具过滤"：

```python
class DeferredToolMiddleware(AgentMiddleware):
    def wrap_model_call(self, request, handler):
        # 在 LLM 调用前，过滤掉尚未激活的工具
        filtered_tools = self.visible_tools(request.tools)
        return handler(request.override(tools=filtered_tools))
```

在每次 LLM 调用前，自动过滤掉不需要暴露的工具。

---

## 小结

Middleware 的价值：
- **解耦**：不需要修改 Agent 核心逻辑
- **可复用**：一个 Middleware 可以用在多个 Agent 上
- **可组合**：多个 Middleware 可以链式使用
- **灵活**：可以拦截 Agent 的每个阶段
