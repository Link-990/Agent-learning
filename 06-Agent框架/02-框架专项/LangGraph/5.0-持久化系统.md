# 第五章：持久化系统（Checkpointers + Stores）

前面的章节里，我们构建的 Agent 都是"一次性"的——运行完就结束了，没有记忆。

但真实的 Agent 应用需要**记忆**：
- **短期记忆**：这次对话的历史（Checkpointer）
- **长期记忆**：跨对话、跨用户的知识（Store）

这一章我们学习 LangGraph 的持久化系统——让 Agent 拥有记忆。

## 两种持久化机制

LangGraph 提供两种持久化机制：

### 1. Checkpointer（检查点）

**作用**：保存**每次执行的完整状态**。

**用途**：
- 对话历史（消息列表）
- 中间状态（变量、计数器等）
- 暂停/恢复（Human-in-the-Loop）

**特点**：
- 每个 `thread_id` 一个独立的 checkpoint 链
- 可以回溯到任意历史状态
- 占用空间较大（保存完整状态）

### 2. Store（存储）

**作用**：保存**跨线程的长期知识**。

**用途**：
- 用户偏好设置
- 知识库
- 跨对话的记忆（比如用户之前提到的信息）

**特点**：
- 用 `namespace` 组织数据（比如 `("user", user_id)`）
- 所有线程共享
- 更灵活的查询（搜索、过滤）

---

## 对比：Checkpointer vs Store

| 特性 | Checkpointer | Store |
|------|-------------|-------|
| 保存内容 | 完整的执行状态 | 结构化的键值对 |
| 作用域 | 每个 thread_id 独立 | 跨 thread 共享 |
| 用途 | 对话历史、暂停/恢复 | 长期记忆、知识库 |
| 查询方式 | 按 thread_id + checkpoint_id | 按 namespace + 搜索条件 |
| 空间占用 | 较大 | 较小 |

---

## 一个例子理解两者的区别

### 场景：客服机器人

**Checkpointer 保存**：
- 当前对话的消息列表
- Agent 的中间状态（比如"正在等待用户确认"）

**Store 保存**：
- 用户的历史订单信息
- 用户的偏好设置（语言、通知方式）
- 常见问题的答案（FAQ）

用户开启新的对话（新的 `thread_id`）时：
- Checkpointer 是**空白**的（新对话）
- Store 里的数据还在（历史订单、偏好设置）

## 何时需要 Checkpointer？

如果你的 Agent 需要：
1. **多轮对话**：记住之前说了什么
2. **暂停/恢复**：执行到一半暂停，等待人工审批，然后继续
3. **时光倒流**：回到之前的某个状态重新执行

那么你需要 Checkpointer。

---

## 何时需要 Store？

如果你的 Agent 需要：
1. **记住用户信息**：跨对话记住用户的偏好、历史
2. **知识库**：存储 FAQ、文档、产品信息
3. **跨用户共享**：所有用户都能访问的公共知识

那么你需要 Store。

---

## 可以同时使用吗？

**可以！** 很多实际应用都会同时使用：

```python
from langgraph.checkpoint.memory import MemorySaver
from langgraph.store.memory import InMemoryStore

checkpointer = MemorySaver()      # 对话历史
store = InMemoryStore()           # 用户偏好、知识库

@entrypoint(checkpointer=checkpointer, store=store)
def my_agent(...):
    ...
```
